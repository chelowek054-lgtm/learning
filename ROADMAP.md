## 2. Как вести этот файл

### Легенда статусов

| | Значение |
|---|---|
| ✅ `done` | завершено **и** удовлетворяет Definition of Done (есть проверка, результат зафиксирован честно) |
| 🟡 `wip` | в работе |
| ⚪ `todo` | не начато |
| 🔴 `blocked` | заблокировано (указать чем) |

### Идентификаторы

`P<фаза>-<поток>-<номер>` — например `P0-WS1-03`, `P2-KG2-01`. Потоки внутри фазы независимы и могут вестись параллельно.

### Правила обновления

1. **Прогресс фиксируется здесь и в плане фазы.** Детальные чеклисты живут в [`docs/plans/phase-*.md`](./docs/plans/README.md); этот файл — сводка и журнал.
2. **`done` только с доказательством.** Указывать способ проверки: *live-прогон* (реальный запуск), *typecheck+bundle* (собралось, но рантайм не прогонялся), *тест*. Не выдавать одно за другое.
3. **Изменение архитектуры — сначала в `docs/architecture/`,** затем в план фазы, затем сюда.
4. **Закрыл поток → добавь строку в [Журнал](#7-журнал-прогресса)** с датой, объёмом и способом проверки.
5. **Разрешённый открытый вопрос** переносится в архитектурный документ, а в [реестре](#5-реестр-открытых-вопросов) помечается решением.

**Ключевые технические решения фазы:**

- **uv** вместо poetry для Python (закрыт открытый вопрос).
- **raw `expo-sqlite`** вместо drizzle-orm — drizzle-миграции требуют codegen и Metro-конфиг под `.sql`, непроверяемо без устройства; порт `LocalStore` абстрагирует БД, замена возможна позже без изменения ядра.
- **Платформенная замена** `sqlite-local-store.web.ts` (in-memory) — `expo-sqlite` на web тянет `wa-sqlite.wasm` (COEP/OPFS), избыточно для mobile-first.
- **Оркестрация в корне суперпроекта**, `Dockerfile` — в сабмодуле сервиса. Новый сервис = блок в корневом compose + свой Dockerfile в его репозитории.
- **Понижение Expo SDK 57 → 54** (RN 0.81, React 19.1, TS 5.9) — ради совместимости с публичным Expo Go на устройстве.

### 3.3 Фаза 2 — Модель знаний · 🟡 в работе · 9/21

**Цель:** построить слой модели знаний (граф концепций как ядро-актив) и доказать на ML цепочку: *канонический граф → наследование новым пользователем (COW) → адаптивный плейсмент → генерация курса до целевого уровня*, где узел хранит формализованную теорию, из которой генерятся тест и практика.

Архитектура слоя — [05 — Модель знаний](./docs/architecture/05-knowledge-model.md). Слой лежит **над** движком Activity; ядро остаётся доменно-независимым — граф это данные модуля, а не логика `shared/engine`.

**Зафиксированные решения фазы:**

- **Первая тема** — ML/программирование (граф естественно иерархичен).
- **Источник графа** — LLM генерирует → пользователь правит (Approve / Edit / Reject).
- **Канон ↔ персонал** — **copy-on-write**: новый пользователь читает канон сквозняком, правка или рост создают персональный узел поверх; улучшения канона видны всем, у кого узел не перекрыт.
- **Тир узла** — `core` (фундаментальное **обязательное** ядро) vs `derived` (вытекающие ветви поверх ядра).
- **Курс = симуляция развития** (укоренение → дифференциация → ветвление → спираль), а не топосорт.

### 3.5 Фаза 4 — Продукт · ⚪ ожидает

Не декомпозирована. Планируемый объём:

## 4. Что дальше

**Ближайший шаг — `KG3`:** структура `content` узла → `generate_assessment(content, bloom, kind)` → кэш `assessment` с привязкой к `concept_version`.

Почему именно он: `KG4` (плейсмент) не может подбирать зонды, пока их нечем генерировать, а `KG5` (курс) не может строить цепочки активностей без оценок. `KG3` — узкое место фазы.

Порядок остатка фазы: **KG3 → KG4 → KG5**, затем прогон инвариантов и сквозной сценарий фазы.

Параллельно, не блокируя фазу: рантайм-прогон клиента на устройстве (см. риски), линтер границ FSD, CI, политика приватности.

## 8. Как проверить состояние

Весь стенд (Postgres + миграции + API → http://localhost:8000/docs):

```bash
docker compose up --build
```

Клиент — типы и тесты:

```bash
cd learningFront && npm run typecheck && npm run test
```

Backend — формат, линтер, тесты:

```bash
cd learningBack && uv run ruff format --check . && uv run ruff check . && uv run pytest
```

Клиент — всё сразу:

```bash
cd learningFront && npm run check
```

Клиент на телефоне/в браузере ходит по `EXPO_PUBLIC_API_BASE_URL` из **корневого `.env`** (в `learningFront/.env` он переносится автоматически перед `npm start`/`web`). Там **IP машины**, который меняется при смене сети (Wi-Fi ↔ Ethernet ↔ хот-спот). Если вход «не проходит», сперва сверить адрес:

```bash
ipconfig | grep -A2 "IPv4"
```

Инвариант доменной независимости ядра — вывод должен быть пустым:

```bash
grep -rniE "languages|ielts|toefl|concept_edge" learningFront/src/shared/engine
```

## 9. Метрики эффективности продукта

Читаются из единого `response`-лога (инвариант №4) — отдельная аналитическая инфраструктура не нужна.

- **Удержание (SRS):** доля карточек, вспоминаемых с первого раза, во времени.
- **Рост по рубрикам:** динамика band/score продукции по критериям.
- **Закрытие error-log:** как быстро ошибки перестают повторяться после попадания в SRS.
- **Регулярность:** длина серий ежедневных сессий как прокси вовлечённости.
- **(с Фазы 2) Объём знаний:** размер выращенного подграфа (узлы × глубина × ступень Блума); **уровень** = положение фронтира.
