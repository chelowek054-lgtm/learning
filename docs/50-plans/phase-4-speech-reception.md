## Новые внешние зависимости

Впервые нужен не только текстовый LLM: **STT** (речь → текст) и **TTS** (текст → речь). Оба подключаются портами в `core/` рядом с `AIGateway`. Реализация выбирается конфигом, ключи — только на backend (NFR-02).

## Потоки

```
PRIV Политика голоса ──► (первая запись)
WS1 Медиа-конвейер ──┬─► WS2 STT + воркер ──► WS3 Speaking
                     └─► WS5 Listening
WS4 Reading (параллельно, звука не требует) ──► WS6 Генерация материалов
```

**Порядок:** PRIV-01, WS2-00 и WS2-03 (решения) → WS1 → (WS2 → WS3) ∥ WS4 → WS5 → WS6.

## Проверки конца фазы

- [ ] Speaking: запись офлайн → STT → оценка → ошибки в SRS — **на устройстве**.
- [ ] Reading и Listening проходятся в самолётном режиме; разбор догоняет при сети.
- [ ] Ключи STT/TTS не в клиенте и не в git; записи удаляются по политике.
- [ ] `shared/engine` не знает про аудио: запись и проигрывание — в `features`, порты — в `shared/api` и `core/`.
- [ ] Единый `response`-лог питает FSRS и метрики для новых типов так же, как для старых.
- [ ] Сверка SPEC-14, SPEC-15 с кодом.

## Открытые вопросы

Оценка произношения; число прослушиваний; стоимость STT/TTS на регулярном использовании — считать после первых замеров. Детали — в SPEC-14 и SPEC-15.
