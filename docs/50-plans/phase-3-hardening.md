## Почему эта фаза

При переходе на DocDD сверка документации с кодом показала: следующий шаг (речь) невозможно честно сделать поверх текущего состояния.

- **Клиент ни разу не запускался на устройстве.** Три фазы проверены только сборкой и web. Речь — это микрофон, её в web не проверить.
- **Нарушен инвариант №3 на backend.** `core/` импортирует модуль `languages` и знает имена модулей.
- **Прогресс повторений теряется.** Клиент не отправляет FSRS-состояние на сервер.
- **Стоимость LLM не видна.** Учёт токенов и кэш генерации в Ф1 были отмечены сделанными, но их нет.
- **CI нет.** Проверки прогоняются руками; форматтер уже однажды разъехался на 40 файлов.

## Потоки и зависимости

```
DEV  Устройство ─────────────┐  (блокирует закрытие клиентских задач и всю Ф4)
CI   Автоматические проверки ─┤
INV  Инварианты backend ──► AI-01 (рубрики через реестр модулей)
                        └──► INV-02 (провижининг по предмету)
SRS  Повторение (ADR-0015) ──► SYNC-02 (push прогресса)
SYNC Синхронизация
AI   Стоимость LLM
KG   Долги графа
UX, DOC
```

**Порядок:** DEV-01 и CI-01..02 — первыми и параллельно: одно даёт рантайм, другое — страховку для остального. Затем INV-01 и SRS-01: оба меняют контракты. За ними — остальное в любом порядке. DEV-02..03 повторяются в конце фазы как приёмка.
