# Перенос контекста

Файл для того, кто продолжает работу с чистого листа — человек или новая сессия ассистента. Здесь то, что **не выводится из кода и истории коммитов**: как запустить, где грабли, какие решения приняты и почему.

Прогресс и статус фаз — в [`ROADMAP.md`](../ROADMAP.md). Устройство системы — в [`docs/architecture/`](./architecture/README.md). Дублировать их здесь не нужно.

**Снимок на:** 2026-08-25

---

## 1. Что это

Praxis — персональный адаптивный тренажёр (Expo/React Native + FastAPI + Postgres). Два движка эффективности: интервальное повторение на FSRS и практика с AI-скорингом по рубрикам. Поверх них — модель знаний: граф концепций, из которого строятся проверка уровня и персональный курс.

Репозиторий — **git-суперпроект** с двумя сабмодулями:

```
D:\work\learning            docs, ROADMAP, docker-compose, .env    ← суперпроект
├── learningBack            FastAPI, Postgres, слой знаний          ← сабмодуль
└── learningFront           Expo/React Native по FSD                ← сабмодуль
```

У каждого сабмодуля своя ветка `main` и свой origin. **Коммитить и пушить нужно все три**, а в суперпроекте ещё и поднять указатели сабмодулей — иначе изменения не увидит никто, кроме вашей машины.

## 2. Запуск

```bash
docker compose up -d --build      # Postgres + миграции + API + pgAdmin
```

| Сервис | Адрес |
|---|---|
| API (Swagger) | http://localhost:8000/docs |
| Админка | http://localhost:8000/admin |
| pgAdmin | http://localhost:5050 |
| Клиент (web) | http://localhost:8081 |

Клиент отдельно:

```bash
cd learningFront && npm run web
```

Проверки:

```bash
cd learningBack && uv run ruff format --check . && uv run ruff check . && uv run pytest
```

```bash
cd learningFront && npm run check
```

`npm run check` — это typecheck + lint + format:check + тесты одной командой.
Форматтер входит в проверку намеренно: пока он был только «доступен», но нигде
не вызывался, к 2026-08-25 разъехался 21 файл из 69 на backend и 19 на клиенте.

Администратор заводится из CLI:

```bash
docker compose exec api uv run python -m scripts.createsuperuser
```

## 3. Грабли этой среды

Всё ниже стоило нескольких неудачных попыток — не наступайте повторно.

**Системный прокси на `127.0.0.1:10809`.** `curl` без `--noproxy '*'` ходит через него и получает 503 от прокси, а не от сервиса. Любой запрос к локальному API — только с `--noproxy '*'`.

**Git Bash ломает кириллицу в теле запроса.** `curl -d '{"topic":"Трансформеры"}'` даёт `400 error parsing the body`. Это оболочка, не приложение. Слать нужно из Python: `subprocess.run(cmd, input=json.dumps(body, ensure_ascii=False).encode("utf-8"))` с `--data-binary @-`.

**Абсолютные пути в `docker compose exec` тоже ломаются** — Git Bash превращает `/usr/local/...` в `C:/Program Files/...`. Помогает префикс `MSYS_NO_PATHCONV=1`.

**Демон Docker не достаёт `ghcr.io`** (TLS handshake timeout), хотя хост достаёт. Поэтому `uv` в образе ставится из PyPI, а не копируется из `ghcr.io/astral-sh/uv`. Не «оптимизируйте» обратно.

**Порт 8081 может быть занят** вашим же dev-сервером Expo — проверьте, прежде чем поднимать второй.

**Тестовая база пересоздаётся** (`drop_all` + `create_all`) на каждый прогон pytest. Так сделано намеренно: `create_all` не эволюционирует существующие таблицы, и добавленная в модель колонка молча не появлялась в тестовой БД — 12 тестов падали с ошибкой драйвера.

**Типы роутов Expo (`.expo/types/router.d.ts`) устаревают.** Они генерируются dev-сервером, а не `expo export`. Если `tsc` ругается, что `/course` не является валидным путём, — удалите файл или запустите `npm run web`. `.expo/` в gitignore.

**Адрес backend в клиенте протухает при смене сети.** `EXPO_PUBLIC_API_BASE_URL` живёт в корневом `.env`; вход падает с «нет связи», если IP машины сменился. Сверяйтесь с `ipconfig`. Править нужно корневой файл: `learningFront/.env` генерируется из него и перезаписывается на каждом `npm start`/`web`.

## 4. Решения, которые стоит знать

**Ключи LLM — только на backend** (инвариант №2). В клиенте их нет и быть не должно.

**Провайдер LLM задаётся адресом, а не кодом.** Один класс `OpenAICompatibleGateway` обслуживает любой сервис с `/chat/completions` и tool calling. Сейчас настроен RouterAI с `deepseek/deepseek-v4-flash-0731`; смена провайдера — это `LLM_BASE_URL`, `LLM_API_KEY` и слаги моделей в `.env`, без правки кода. Отдельных классов под конкретных вендоров в коде нет намеренно: 2026-08-25 из него убраны и путь через Anthropic SDK, и подхват старого `OPENROUTER_API_KEY` — они делали выбор провайдера частью кода.

**`max_tokens` обязателен в каждом запросе.** Без него провайдер резервирует весь контекст модели и отклоняет запрос как неоплачиваемый. На это ушёл час.

**Транспорт к провайдеру повторяет запрос трижды** — канал рвётся примерно на каждом третьем запросе, при 402 бюджет подстраивается под остаток кредита, а модель иногда отвечает текстом вместо вызова инструмента. Все три случая лечатся повтором.

**Граф знаний — данные модуля, а не логика ядра.** Он живёт в `learningBack/modules/knowledge/`; в `core/` его нет, и это проверяется grep'ом. То же на клиенте: `shared/engine` про граф не знает.

**Курс закрывает шаг достигнутой освоенностью, а не нажатием кнопки.** Ответ идёт в единый `response`-лог, оттуда в модель освоенности; слабый ответ возвращает узел через FSRS.

**Окружение — в одном файле.** Корневой `.env` суперпроекта настраивает всё: его читает docker-compose, его же читает `learningBack/core/config.py` (а не свой), из него `learningFront` переносит `EXPO_PUBLIC_*` в собственный `.env` перед каждым `npm start`/`web` (Expo умеет читать только свой корень). Своих `.env`/`.env.example` у сабмодулей больше нет: 2026-08-25 их было три, и они расходились молча — ключ лежал в одном файле, а адрес провайдера в другом, из-за чего приложение молча работало на заглушках. `DATABASE_URL` тоже не дублируется — собирается из `POSTGRES_*`, compose лишь подменяет хост на имя сервиса.

**Интерфейс говорит от задачи человека, а не от модели системы.** Названия активностей живут в `ActivityTypeDef.title`, уровни — в `MASTERY_TARGETS`, причина шага — в `StepReason`. Каждый из этих словарей до 2026-08-25 существовал в двух-трёх экранах сразу и успел разойтись, а часть внутренних меток (слуги типов, ступени Блума по-английски, `centrality`/`origin`/`status`) просто выводилась наружу. Новый экран не заводит свою карту названий — спрашивает у реестра.

**Область изучения — из профиля, а не из кода.** `profile.subject` (`id`, `title`, `target`) читается через `useSession().subject`; строки `'ml'` в экранах больше нет. Домен попадает в путь URL, поэтому все сегменты кодируются: предмет с кириллицей ломал бы запросы.

**Пустую область заводит тот, кто выбрал предмет.** Право на `/graph/canon/build` открыто любому пользователю, пока в области нет ни одного узла; достройка и `refresh` — только администратору. Иначе выбор нового предмета был тупиком: карты нет, строить некому. Построенные узлы — `status="draft"`, то есть непроверенные; в графе это видно по полю `reviewStatus` (не путать с `status`, который про персональный слой), в интерфейсе — меткой «не проверено». Вычитывает их куратор через `approve`.

**Курирование графа отделено от учёбы структурой.** `GraphMap` — чтение, `GraphCuration` — канон; экран выбирает по `isAdmin`. Раньше это был один компонент, и правка узлов была открыта любому.

**Оформление — в одном файле.** `learningFront/src/shared/config/design.ts`: цвета, кегли, отступы. Больше ни один файл не объявляет hex. Тема поддерживает системный режим и явный выбор светлой/тёмной.

## 6. Открытые долги

| Долг | Почему важен |
|---|---|
| Клиент не запускался на устройстве | Блокирует Фазу 3; накоплен объём двух фаз |
| Новичку выдаётся колода AWL независимо от предмета | Провижининг из Ф1 сеет английскую лексику всем; у человека с предметом «Теория музыки» первым шагом идёт повторение чужих слов |
| Тип `srs` объявлен только на клиенте | Шаг курса отдаёт `srs`, а backend-модуль ml объявляет `concept_srs` — типы разошлись, и у `srs` нет рендерера |
| Персональные узлы графа без версии | Задания по ним не генерируются |
| Обновление теории идёт по совпадению заголовка | Если модель предложит другие названия, старые узлы останутся и граф засорится |
| Политика хранения текстов и голоса | Голос — биометрия; решить до первой записи |
| Нет CI | Проверки прогоняются руками |

## 7. Как работать дальше

Правила, по которым велась работа, — не бюрократия, а то, что позволяло не потерять нить:

1. **Прогресс фиксируется в `ROADMAP.md`** при каждом закрытом потоке: дата, объём, способ проверки.
2. **`done` только с доказательством.** Различать *live-прогон*, *typecheck+bundle* и *тест* — и не выдавать одно за другое. Половина найденных дефектов всплыла именно на живом прогоне, а не в тестах.
3. **Изменение архитектуры — сначала в `docs/architecture/`,** потом в план фазы, потом в код.
4. **Найденное по дороге записывать честно**, даже если это ломает красивую картину: неработающий клиент, засвеченный ключ, инверсия в модели освоенности.
