# 30 — Архитектура

Как система **устроена**: стек, топология, слои, модель данных, модульная система, организация клиента, модель знаний. Что система **делает** — в [требованиях](../10-requirements/README.md) и [спеках](../20-specs/README.md); **почему** устроена так — в [ADR](../40-adr/README.md).

Изменение устройства идёт по порядку: ADR → документ этого раздела → затронутые спеки → план ([правила DocDD](../README.md#правила-docdd)).

---

## Документы

| Документ | Назначение | Решения |
|---|---|---|
| [01 — Архитектурный план](./01-architecture.md) | Стек, топология, online/offline, границы систем, структура репозитория, deployment | ADR-0002, 0004, 0006–0010 |
| [02 — Логический план](./02-logical.md) | Activity, модель данных ядра, модульная система, FSRS, sync и очередь задач, AI-gateway, `Grade` | ADR-0004, 0005, 0009, 0014 |
| [03 — Функциональная архитектура](./03-functional.md) | Модули (`languages`, `ml`, `knowledge`), их типы Activity и рубрики, сквозные сценарии | — |
| [04 — Фронтенд (FSD)](./04-frontend-fsd.md) | Слои FSD, размещение ядра, сборка модулей, expo-router | ADR-0003, 0017 |
| [05 — Модель знаний](./05-knowledge-model.md) | Граф (канон + персонал, COW), узел-контент, задания, освоенность, плейсмент, курс | ADR-0011–0013, 0016 |

## Порядок чтения

1. [Видение](../00-product/vision.md) и [инварианты](../10-requirements/non-functional.md#инварианты-системы).
2. `01 → 02 → 03`: от стека к данным, от данных к модулям.
3. `04` — если работаете с клиентом; `05` — если с графом, плейсментом или курсом.
