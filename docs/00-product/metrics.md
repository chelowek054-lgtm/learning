# Метрики

## Метрики эффективности обучения

Все метрики читаются из единого лога `response` (инвариант №4), поэтому отдельная аналитическая инфраструктура не нужна. Сбор и показ этих метрик — требование `FR-UX-07`.

| Метрика | Как считается | Что подтверждает |
|---|---|---|
| **Удержание** | Доля карточек, вспомненных с первого раза, во времени | Работает движок FSRS |
| **Рост по рубрикам** | Динамика `overall` и баллов по критериям у продукции одного типа | Главная гипотеза: оценка по рубрике даёт прирост |
| **Закрытие error-log** | Как быстро ошибка одного `kind` перестаёт повторяться после попадания в SRS | Связка двух движков работает |
| **Объём знаний** | Размер освоенного подграфа: узлы × ступень Блума | Курс по графу ведёт к цели |
| **Положение границы** | Доля узлов `known` среди нужных для цели | Уровень относительно цели |
| **Регулярность** | Длина серии ежедневных сессий | Прокси вовлечённости |

## Метрики качества системы

| Метрика | Цель | Где проверяется |
|---|---|---|
| Время планирования карточки FSRS | < 16 мс, офлайн | `NFR-08` |
| Доля заданий, построенных из теории узла (не отсечённых) | Растёт с курированием | `FR-ASM-01` |
| Расход токенов на пользователя в день | Считается, лимит — после замеров | `FR-AI-05` |
| Доля job в `failed` | Стремится к 0 при сети | `FR-SYNC-06` |

## Чего не измеряем

Время в приложении и число открытий. Эти метрики поощряют удержание внимания, а не обучение.
