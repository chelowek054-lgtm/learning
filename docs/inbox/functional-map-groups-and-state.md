# Функциональная карта: привести группы и состояние реализации к фактам

## Зачем

Функциональная карта должна быть главным источником правды о приложении: что система умеет, чего не умеет и чего ещё нет. Сейчас в ней 16 возможностей, у большинства нет отметки реализации (14 «не оценено», остальные без отметки), а целые направления, которые появились после её составления, на ней отсутствуют. Карту нужно довести до фактического состояния и дальше вести её первой при любом изменении.

## Что считается сделанным

Группы карты отражают реальность. Новые большие группы, которых не хватает:

- **Платформа с подключаемыми модулями** (под назначением продукта): единый контракт модуля и реестр, граф знаний как независимый модуль без предметов, способы запоминания и мини-игры как модули, единое хранилище данных пользователя с доступом по разрешениям, изоляция модулей и защита от утечек. Всё это задумано, кода под большую часть ещё нет — состояние «не реализовано», у реестра модулей и независимости ядра от предметов — «реализовано».
- **Задачи на код** (подгруппа ML-трека): ревью по рубрике без запуска кода с пометкой об ограничении, экран задачи с офлайн-черновиком, практика узла технического предмета как задача на код.
- **Письмо TOEFL** (подгруппа письма): два типа задания и две рубрики, тип выбирается по предмету.
- **Прогресс учащегося** (подгруппа опыта учащегося): удержание, рост по рубрикам, закрытие ошибок, граница знаний, серия занятий.
- **Промоция персональных узлов в канон** (подгруппа администрирования и курирования).
- **Авто-синхронизация и инкрементальный sync** (подгруппа синхронизации).
- **Безопасность аккаунта** (подгруппа аккаунта и ролей): хеш кода восстановления, ограничение запросов кода, отзыв сессий при смене пароля; запрет запуска в staging и production с dev-секретами (подгруппа платформы и релиза).

Состояние реализации выставлено по фактам и честно разделено: «реализовано» — есть код и автотесты; «частично» — код есть, но проверка на устройстве или с живым провайдером не проходила (так сейчас у шага повторения в курсе, авто-синхронизации, инкрементального sync, экрана задачи на код, экрана прогресса); «не реализовано» — кода нет (платформа, речь, чтение и аудирование, политика данных); «не оценено» остаётся только там, где никто не смотрел.

## Чего не делаем

- Не выставляем «реализовано» там, где нет прохода на устройстве, если требование этого требует: это «частично».
- Не заводим по возможности отдельных требований прямо в карте: связь с требованиями идёт в записях, карта остаётся языком предметной области.

## Что мешает

- Часть возможностей описана в карте крупно; при подвешивании новых подгрупп придётся уточнить родителей существующих (например, где именно живёт «Письмо IELTS» и «Письмо TOEFL»).

## Не выяснено

- Одна ли группа «Письмо» с двумя подпунктами IELTS и TOEFL или две соседние группы.
