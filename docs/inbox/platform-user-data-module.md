# Данные пользователя: единое хранилище с доступом по разрешениям

## Зачем

Данные учащегося — ответы, оценки, освоенность, карточки, заметки, результаты мини-игр, голос — самое ценное и самое опасное в системе. Если каждый модуль хранит свои данные как хочет, защитить их нельзя, а человек не может уйти, не потеряв прогресс. Поэтому данные принадлежат платформе: хранит их отдельный модуль, а остальные модули получают к ним доступ через него, по разрешениям.

Это же даёт то, ради чего затеяна платформа: человек меняет способ запоминания, а накопленное остаётся с ним.

## Что считается сделанным

- Все данные пользователя лежат в одном хранилище с единым журналом событий; модуль не заводит собственных таблиц с личными данными в обход него.
- У каждого типа данных есть владелец (человек), назначение и срок хранения; это описано, а не подразумевается.
- Модуль получает доступ только к тем типам данных, которые объявил в манифесте и которые человек разрешил; доступ на чтение и на запись разрешается отдельно.
- Любой доступ модуля к данным пишется в журнал: кто, что, когда, зачем. Человек может его прочитать.
- Человек может отозвать разрешение модулю, выгрузить свои данные целиком и удалить их; удаление доходит и до данных, которые модуль успел запросить.
- Данные модуля, не относящиеся к личным (настройки игры, её контент), хранятся отдельно и удаляются вместе с модулем.
- Офлайн-режим сохраняется: локальное хранилище на устройстве остаётся источником правды для действий, синхронизация идёт через платформу.

## Чего не делаем

- Не отдаём модулю «весь профиль» по умолчанию.
- Не позволяем модулю отправлять личные данные наружу в обход платформы (см. заметку о защите от утечек).
- Не смешиваем данные разных людей в одном ответе модулю: модуль видит только текущего пользователя.

## Что мешает

- Политика данных (что храним, где, сколько, что видит каждый провайдер) ещё не написана; без неё нельзя описать владельца и срок для каждого типа.
- Сейчас данные размазаны: ответы, карточки и освоенность лежат в разных таблицах и пишутся разными частями системы.
- Голос — биометрия: правила его хранения нужно решить до первой записи.

## Не выяснено

- Модель разрешений: список типов данных, выбор человека при установке модуля или постоянная настройка.
- Можно ли модулю хранить производные данные (например, рекомендации), и кому они принадлежат.
- Как выгружать данные в формате, который можно перенести в другую систему.
- Как совмещать это с работой нескольких устройств: где источник правды при конфликте.
