# Решение: объектное хранилище — SeaweedFS через S3 API (предложение)

Хранилище нужно для скачанных и загруженных источников (PDF, HTML) до и после разбора. MinIO Community не подходит: в мае 2025 убрали консоль управления, в октябре 2025 перестали публиковать образы и бинарники, в декабре 2025 репозиторий переведён в режим поддержки, в феврале 2026 заархивирован.

## Варианты (все с API S3)

- **SeaweedFS** (Apache 2.0) — лёгкий, хорошо держит и мелкие, и крупные файлы, подходит для одного сервера.
- **Garage** (AGPL) — лёгкий, для небольших кластеров.
- **Ceph RGW** — зрелый, но тяжёлый для одного сервера.

## Предложение

SeaweedFS; в коде — только S3-совместимый клиент, чтобы замена хранилища не трогала бизнес-логику. Бакеты закрытые, доступ к файлам через подписанные временные ссылки только для администраторов. Входит в `docker-compose` отдельным сервисом, в staging — с резервной копией и проверкой восстановления, как база.

## Не выяснено

- Размер хранилища и срок хранения исходников после разбора (оставлять ли файл или удалять, сохраняя только фрагменты и происхождение).
