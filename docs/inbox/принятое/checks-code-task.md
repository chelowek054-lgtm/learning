# Проверки: Задача на код с ревью по рубрике

## Зачем

Показать фактом, что требование R-0010 выполнено, а не только объявлено. Проверяет требование R-0010; задачи, которые оно порождает, — T-0010, T-0011, T-0012, T-0013. Каждая проверка ниже — отдельная запись-проверка; по ней задача сможет закрыться только с пройденным прогоном.

## Проверка 1: Рубрика ml_code_review

- Вид: unit
- Чем запускается: pytest
- Команда: `будет: cd learningBack && uv run pytest tests/test_code_review_rubric.py -q`
- Что доказывает: Рубрика v1 есть в реестре, четыре критерия, оценка проходит схему.
- Считается пройденной, когда: тест написан вместе с T-0010
- Состояние: ещё нет: появится вместе с задачей
- Проверяет: R-0010; задачи T-0010, T-0011, T-0012, T-0013

## Проверка 2: Job grade_code

- Вид: integration
- Чем запускается: pytest
- Команда: `будет: cd learningBack && uv run pytest tests/test_grade_code_job.py -q`
- Что доказывает: Решение оценивается по рубрике, ошибки становятся карточками, в разборе названо ограничение «код не исполнялся».
- Считается пройденной, когда: тест написан вместе с T-0012
- Состояние: ещё нет: появится вместе с задачей
- Проверяет: R-0010; задачи T-0010, T-0011, T-0012, T-0013

## Проверка 3: Решение задачи на устройстве

- Вид: manual
- Чем запускается: вручную
- Команда: нет, проверка не автоматическая
- Что доказывает: Условие → решение в редакторе офлайн → при сети ревью по четырём критериям → ошибки в повторении.
- Считается пройденной, когда: проходится руками после T-0011 и T-0012
- Состояние: ещё нет: появится вместе с задачей
- Проверяет: R-0010; задачи T-0010, T-0011, T-0012, T-0013
