# Граф знаний: канон, персональный слой, рост

## Зачем

Сделать структуру предмета явной: граф понятий с теорией в узлах, общий для всех (канон) и растущий под каждого (персональный слой). Граф — основа плейсмента, курса и генерации заданий.

## Состояние

частично — чтение, построение, курирование, персональный слой и рост работают; персональные узлы без версии, перегенерация сопоставляет по заголовку

## Как должно вести себя

1. **Чтение.** `GET /graph/{domain}` отдаёт эффективный граф: канонические узлы и рёбра домена, перекрытые персональным слоем пользователя. Новый пользователь ничего не копирует: все узлы `origin='inherited'`.
2. **Построение пустой области.** Любой пользователь вызывает `canon/build`, если в домене нет узлов. LLM возвращает до `max_nodes` (2–20, по умолчанию 8) узлов с теорией, тиром, `confidence` и рёбрами. Узлы сохраняются `source='llm'`, `status='draft'`. Повторный build или `refresh` — только администратор. Существующий узел с непригодной теорией дополняется, если черновик лучше; версия растёт.
3. **Курирование канона** (администратор): создать или изменить узел (правка теории → `version+1`), создать ребро, пересчитать centrality, подтвердить узел (`approve`, можно сменить тир).
4. **Core-детекция.** Centrality = доля узлов, транзитивно зависящих от данного по `prereq`/`specializes`. Кандидат в ядро: centrality ≥ 0.5 **или** узел уже помечен `core`, в том числе LLM при построении. В ядро переводит куратор.
5. **Персональный слой.** Перекрыть теорию канонического узла (`origin='edited'`); создать свой узел и ребро; изменить или удалить свои. Канон при этом не меняется.
6. **Рост.** `expand(concept_id, direction)`: LLM предлагает узлы в направлении интереса; они становятся персональными (`origin='grown_llm'`), рёбра восстанавливаются по ключам, несвязанный узел цепляется к исходному.
7. **Домен в URL** кодируется: предмет с кириллицей работает во всех запросах.

## Что система обязана обеспечить

- Учащийся видит эффективный граф предмета: канон, перекрытый его персональным слоем. Признак: Новый пользователь видит канон без копирования строк. (Сейчас: реализовано; прежний номер — FR-KG-01.)
- Пустую область может построить LLM-черновиком любой пользователь; достройку и перегенерацию — только администратор. Признак: Первый build в пустом домене → 200 для любого; повторный build не-админом → 403; узлы создаются `status='draft'`. (Сейчас: реализовано; прежний номер — FR-KG-02.)
- Администратор курирует канон: создаёт и правит узлы и рёбра, подтверждает узлы, меняет тир, пересчитывает centrality. Признак: Эндпоинты `canon/*` для не-админа → 403; правка теории поднимает версию узла. (Сейчас: реализовано; прежний номер — FR-KG-03.)
- Учащийся правит свой слой: перекрывает теорию канонического узла, создаёт свои узлы и рёбра, удаляет свои. Признак: Перекрытие видно только автору; канон не меняется. (Сейчас: реализовано; прежний номер — FR-KG-04.)
- Учащийся углубляет узел в выбранном направлении; LLM дорастает персональную ветку. Признак: Новые узлы `origin='grown_llm'` связаны с исходным. (Сейчас: реализовано; прежний номер — FR-KG-05.)
- Теория узла имеет фиксированную форму: summary, разделы с примерами и контрпримерами, источники. Признак: Кривая форма от клиента → 422; мусор от LLM отбрасывается без потери узла. (Сейчас: реализовано; прежний номер — FR-KG-06.)
- Персональные узлы версионируются, и по ним генерируются задания. Признак: Правка своего узла поднимает версию; задания по нему генерируются. (Сейчас: принято, не начато; прежний номер — FR-KG-07.)
- Перегенерация теории сопоставляет узлы по устойчивому ключу, а не по заголовку. Признак: Переименование узла моделью не создаёт дубль. (Сейчас: принято, не начато; прежний номер — FR-KG-08.)
