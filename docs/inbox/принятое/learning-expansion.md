# Расширение обучения: код, импорт, Task 1, TOEFL, языковой граф

## Зачем

Довести оба первых предмета до полного объёма (scope): практика с кодом, собственные материалы учащегося как источник графа, оставшиеся форматы письма, граф для языка.

## Состояние

черновик

## Как должно вести себя

### Задача на код (`code_task`, online)

1. Задача из узла графа (практика `apply`/`create`) или из материала: условие, сигнатура, примеры.
2. Учащийся пишет решение в редакторе с моноширинным шрифтом; решение сохраняется офлайн.
3. Job `grade_code` по рубрике `ml_code_review` v1: Correctness, Numerical stability / Efficiency, Idiomatic style, Explanation (0–5). Код **не исполняется** на сервере; ревью статическое, это ограничение показано в разборе.
4. Ошибки → карточки повторения.

### Импорт материалов (`importers` манифеста)

1. Учащийся загружает PDF или Markdown (≤ 20 МБ). Backend извлекает текст с разбивкой на фрагменты и сохраняет `material {source: pdf|note, user_id}`.
2. По материалу LLM предлагает узлы и рёбра **персонального** слоя; теория узла ссылается на фрагменты (`references`), узлы `source='material'`.
3. Из материала генерируются вопросы `concept_recall` (оживает `concept_recall_from_material`).

### Письмо: Task 1 и TOEFL

1. `ielts_writing_task1`: задание с данными (таблица/график в `payload` как структура + изображение), 150 слов, рубрика `ielts_writing_task1` (Task Achievement вместо Task Response).
2. Рубрики `toefl_writing_integrated` и `toefl_writing_independent` в реестре; тип Activity выбирается по цели из профиля.
3. Полный Academic Word List вместо демо-выборки.

### Граф языкового домена

Исследовательская задача: как ложатся канон, ядро и курс на язык, который менее иерархичен, чем ML. Результат — ADR и, если подтвердится, граф «Английский B2» с ядром (грамматические конструкции, частотная лексика) и курсом, в который встроены дриллы SPEC-15.

### Экран прогресса

Метрики из metrics.md по данным `response`: удержание, рост по рубрикам по критериям, закрытие error-log, доля `known` среди узлов цели.

## Что система обязана обеспечить

- Учащийся пишет IELTS Task 1 (описание графика или таблицы). Признак: Задание с данными; оценка по рубрике Task 1. (Сейчас: принято, не начато; прежний номер — FR-WRT-04.)
- Учащийся тренирует письмо TOEFL (integrated / independent). Признак: Рубрики TOEFL в реестре; эссе оценивается по ним. (Сейчас: принято, не начато; прежний номер — FR-WRT-05.)
- Учащийся решает задачу на код и получает ревью по критериям. Признак: Ревью по рубрике `ml_code_review`: корректность, эффективность, стиль, объяснение. (Сейчас: принято, не начато; прежний номер — FR-ML-03.)
- Учащийся загружает PDF или Markdown; материал заземляет узлы графа. Признак: Узлы из материала имеют `source='material'` и ссылки на фрагменты. (Сейчас: принято, не начато; прежний номер — FR-ML-04.)
- Граф работает для языкового домена. Признак: Предмет «Английский B2» получает граф с ядром и курсом. (Сейчас: предложено; прежний номер — FR-KG-10.)

## Что считается сделанным

- Решение `code_task` получает ревью по 4 критериям; ошибки в повторении — проверка: live; сейчас: не сделано. (прежний номер AC-16.1)
- PDF превращается в материал, читаемый офлайн — проверка: live; сейчас: не сделано. (прежний номер AC-16.2)
- Узлы из материала — персональные, `source='material'`, со ссылками на фрагменты — проверка: test; сейчас: не сделано. (прежний номер AC-16.3)
- Task 1 оценивается по своей рубрике — проверка: live; сейчас: не сделано. (прежний номер AC-16.4)
- Учащийся с целью TOEFL получает TOEFL-задания и рубрики — проверка: live; сейчас: не сделано. (прежний номер AC-16.5)
- ADR по языковому графу принят; решение отражено в [30-architecture/05](../30-architecture/05-knowledge-model.md) — проверка: ревью; сейчас: не сделано. (прежний номер AC-16.6)
- Экран прогресса показывает метрики из `response` — проверка: live; сейчас: не сделано. (прежний номер AC-16.7)
