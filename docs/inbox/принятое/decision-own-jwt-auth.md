# Решение: Собственный JWT в FastAPI вместо Supabase Auth

Когда принято: 2026-07-04. Статус: принято.

## Зачем решали

На Ф0 оставался открытым вопрос: Supabase Auth или собственный JWT. Backend уже был, Postgres локальный, и внешних зависимостей хотелось меньше.

## Что решили

Аутентификация сделана в FastAPI: пароли хешируются argon2 (`pwdlib`), токен — HS256 JWT с секретом из окружения и сроком 30 дней. Роль `is_superuser` выдаётся только из CLI. Пароль восстанавливается одноразовым 8-значным кодом из собственной таблицы.

## Отвергнуто и почему

- **Supabase Auth**: за — Готовые письма, OAuth; против — Внешняя зависимость, вторая БД пользователей.
- **Свой JWT**: за — Всё в одном backend, работает локально; против — Доставку писем, отзыв токенов и rate-limit делаем сами.

## Последствия

Доставка и хеширование кода, отзыв сессий и rate-limit — задачи Ф6 (P6-AUTH-01..02).
