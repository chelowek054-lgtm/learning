Протухание знаний: срок актуальности утверждений и обновление

Зачем: часть знаний устаревает (версии библиотек, стандарты, статистика, законы, практики), часть — нет (определения, теоремы). Граф без механизма обновления постепенно начнёт учить устаревшему.

Что делаем:
- У утверждения есть класс изменчивости: устойчивое (определения, теоремы — не устаревает), медленное (практики, стандарты — пересмотр раз в 2–3 года), быстрое (API, версии, цифры, нормы — раз в 6–12 месяцев). Класс ставится при извлечении в том же запросе, без отдельного обращения, а по умолчанию задаётся областью.
- У утверждения есть «актуально на» — дата источника, и «пересмотреть после» — дата плюс срок по классу.
- Плановая задача без модели находит утверждения с истёкшим сроком и ставит узел на обновление: поиск более новых источников по этому понятию теми же каналами; найденное идёт по обычному конвейеру.
- Если более новый источник не ниже по доверию противоречит старому утверждению быстрого класса — это кандидат на замену: старое утверждение помечается «заменено» (история сохраняется), узел пересобирается. Для устойчивого и медленного класса — в пул проблем к администратору.
- Утверждения с областью применимости («до версии 3.11», «с 2024 года») не считаются противоречием друг другу.
- Учащийся видит у теории «актуально на дату». Если утверждение, которое он изучал, заменено, связанные карточки пересобираются и узел попадает в повторение.
- Ссылки на оригинал периодически проверяются; мёртвая ссылка помечается, сохранённый текст фрагмента остаётся.

Готово, когда: у каждого утверждения есть класс и дата пересмотра; просроченные узлы сами ставятся на обновление; замена утверждения видна в истории и возвращает узел в повторение тем, кто его изучал.
