# Переиспользование готовых областей: поиск близких графов вместо повторной генерации

## Зачем

Каждая цель сейчас строится заново, даже если подобная область уже есть у другого человека. Это дорого (токены, время) и размывает базовые графы дублями. Платформа должна перед построением искать уже реализованные области и подключать их ссылками. Возможность в функциональной карте — «Переиспользование готовых областей».

## Что считается сделанным

- Для каждой построенной области сохраняется её описание в виде, пригодном для поиска по близости (векторное представление названия и краткого содержания).
- При построении графа цели для каждого субдомена сначала ищется близкая готовая область; если близость выше порога, человеку показывается «Такая область уже есть: …, подключить?».
- Подключение — ссылка на существующий граф, а не копия: правка куратором общего графа видна всем, кто на него ссылается.
- Если подходящей области нет, строится новая, и она становится кандидатом для следующих целей.
- Поиск не выдаёт чужие личные ветви: ищет только по базовым графам.
- Порог близости и число вариантов настраиваются; ложное совпадение человек может отклонить, и тогда строится новая область.

## Чего не делаем

- Не копируем графы между областями молча.
- Не ищем по личным данным пользователей.

## Что мешает

- Нужно хранилище для поиска по близости; предлагается расширение векторов в той же базе (решение о платформе).
- Без дедупликации базовых графов куратором поиск начнёт возвращать почти одинаковые области; нужен способ слияния.

## Не выяснено

- Как считать «достаточно близко» для областей на разных языках и с разным названием одного и того же.
