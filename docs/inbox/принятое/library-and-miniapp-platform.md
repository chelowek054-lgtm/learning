# «Моя библиотека», общий каталог областей знаний и платформа мини-приложений

Со слов человека (2026-10-07). Это три связанные идеи, одна тема — предмет перестаёт быть настройкой профиля.

## 1. Предмет выносится на глобальный уровень

Сейчас «Предмет» — карточка в «Профиле» с кнопкой «Сменить предмет» (она сбрасывает онбординг); предмет один
(`profile.subject`, `pages/profile/ui/profile-screen.tsx`). Нужно вынести его выше.

- **Моя библиотека:** вкладка (или раздел верхнего уровня) со списком предметов человека. Из неё он
  проваливается в свой граф знаний и курс по этому предмету. Несколько предметов одновременно.
- **Общий пул и каталог (позже):** общий каталог предметов, тем и областей знаний, из которого человек просто
  выбирает, что изучать; выбранное появляется списком в «Моей библиотеке». Рекомендации под пользователя.
  Готовые графы переиспользуются (сопоставление областей уже есть, R-0050).

## 2. Мини-приложения как самостоятельные единицы

Общие мини-приложения (плашки «Сегодня», повторение, чтение материала, проверка уровня, схема графа и др.)
опираются на граф знаний, но являются полноценной самостоятельной кодовой единицей: свой код, свой контракт,
свои данные по разрешению человека. Впоследствии — возможность сторонним разработчикам добавлять свои
мини-приложения, по образцу мини-приложений VK.

## Связь с имеющимися записями

- Вектор проекта (функциональная карта M-0010): «не отдаёт данные мини-приложениям напрямую, только через
  платформу и по разрешению человека»; авторы мини-приложений уже названы в аудитории. Эта заметка развивает
  вектор, а не меняет его.
- R-0059 / T-0111: там прямо написано «не вводим несколько предметов одновременно» и «предмет переключается из
  шапки». Это решение нужно пересмотреть: переключатель в шапке становится входом в «Мою библиотеку».
- Архитектура (D-0001): модули независимы и общаются через шлюз; мини-приложения — продолжение этой идеи наружу.
  Нужно решить границу: что уже модуль платформы, а что станет мини-приложением.
- `today-as-miniapp-tiles` — первые мини-приложения; `client-graph-visualization`, `course-path-tree-and-accordion`
  — вид внутри предмета.
- `user-flow-journey`, открытый вопрос 1 («несколько предметов или один активный») — этим он закрывается: несколько.

## Что считается сделанным на первом шаге (без каталога и сторонних разработчиков)

1. Список предметов человека («Моя библиотека»): добавить, открыть, поставить на паузу, удалить предмет.
   Открыть — значит войти в «Сегодня / Путь / Прогресс» этого предмета.
2. Активный предмет запоминается; шапка вкладок показывает его и ведёт в библиотеку.
3. Повторение остаётся общим для всех предметов, с подписью предмета.
4. Контракт мини-приложения описан документом (какие данные граф отдаёт, какие события принимает, какие права
   запрашивает) и по нему сделана хотя бы одна плашка «Сегодня» как отдельная единица.

## Чего не делаем сейчас

Каталог, рекомендации, публичный магазин мини-приложений, модерацию сторонних — это следующие шаги; здесь только
то, без чего их нельзя будет сделать (несколько предметов и граница мини-приложения).

## Что мешает и нужно решить человеку

1. Хранение нескольких предметов: сейчас предмет лежит в `profile.subject` одним значением; нужна запись
   «предмет человека» с состоянием (собирается, идёт, пауза, достигнут) — касается и бэкенда.
2. Где граница мини-приложения: отдельный пакет клиента с контрактом, или модуль на бэкенде со своим экраном.
3. Права и приватность: что мини-приложение видит по умолчанию (политика данных `docs/60-operations/data-policy.md`).
