# Задача: изоляция модулей и защита данных от утечек

## Зачем

Требование R-0030: сторонний модуль не должен достать до чужих данных, выйти в сеть без разрешения и уронить ядро. Без этого нельзя открывать подключение модулей людьми. Задача входит в фазу P-0015 и идёт после контракта, модуля данных и разрешений.

## Что считается сделанным

- Модуль исполняется в изолированной среде без прямого доступа к файлам, базе, секретам и памяти других модулей; единственный путь к данным — интерфейс платформы с проверкой разрешений.
- Сеть для модуля закрыта по умолчанию; объявленные адреса видны человеку при установке и только они открыты.
- Ресурсы ограничены: время, память, число обращений к данным, размер хранилища; превышение останавливает модуль, а не систему.
- Сбой модуля не роняет ядро, пользователь видит понятное сообщение, модуль отключается.
- Обновление модуля, расширяющее разрешения, требует нового согласия человека.
- Специально написанный «злой» модуль не получает чужих данных и не выходит за ограничения (проверка тестом).

## Чего не делаем

- Не полагаемся на честность авторов и не открываем каталог без изоляции и проверки.

## Что мешает

- Не решено, где исполняются модули: на сервере изоляция проще, но офлайн-режим этого не допускает; на устройстве нужна песочница мобильной платформы.
- Нет модуля данных пользователя с разрешениями и контракта с манифестом, в котором разрешения запрашиваются.

## Не выяснено

- Чем исполнять модуль на устройстве: интерпретатор в песочнице, веб-представление с ограничениями или описание без исполнения кода.
- Как отзывать модуль, оказавшийся вредным, у всех пользователей.
