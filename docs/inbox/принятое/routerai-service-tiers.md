# RouterAI: режимы обработки flex и priority (service tiers) (справка провайдера)

Источник: документация RouterAI (получена от человека 2026-10-07).

Режим — приоритет, с которым провайдер выполняет запрос; модель и качество те же, различаются цена и скорость.
Задаётся полем `service_tier` верхнего уровня тела запроса на каждый запрос (не на ключ и не на аккаунт);
работает в Chat Completions, Responses и Messages.

| | `default` (без параметра) | `flex` | `priority` |
|---|---|---|---|
| Цена за токены | стандартная | обычно −50% | выше стандартной |
| Скорость | обычная | ниже, в пик задержка растёт | максимальная, приоритетная очередь |
| Если мощностей нет | резервные провайдеры | ошибка, деньги не списываются | автоматически `default` без доплаты |
| Для чего | повседневное | фоновые и массовые задачи | продукты реального времени |

- Провайдеры: OpenAI (flex и priority), Google Vertex AI (оба), Google AI Studio (оба), xAI (только priority).
  Режимы доступны для отдельных моделей; если модель режим не поддерживает — обслуживается стандартно по обычной цене.
- `flex` строгий: маршрутизация только на flex-совместимых провайдеров; нет ни одного — ошибка (повторить позже
  или без `service_tier`). `priority` деградирует мягко.
- Списание идёт по фактически использованному режиму. Фактический режим — поле `service_tier` ответа
  (Chat Completions/Responses — верхнее поле; Messages — внутри `usage`): `default`, `flex`, `priority` или `null`.
  Для контроля расходов логировать это поле.
- Режим для одного провайдера в списке: суффикс в идентификаторе, например `"provider": {"order": ["openai/priority"]}`.
