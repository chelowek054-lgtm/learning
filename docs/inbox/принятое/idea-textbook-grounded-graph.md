# Идея: графы и курсы строятся по проверенным учебникам, а не по памяти модели

## Что не так сейчас (разбор на реальных данных)

Взят граф «Английский B2» (13 узлов) и построенный по нему курс, плюс граф «Civilization 5».

1. **Узел — это глава учебника, а не понятие.** «Страдательный залог», «Условные предложения и wish», «Стратегии чтения» — по одному узлу. Теория узла — 2–4 предложения и 1–3 раздела, написанные моделью по памяти. Настоящего содержания (правила, исключения, примеры на уровень, упражнения) в графе нет.
2. **Состав графа не воспроизводим и не опирается на программу.** Каждое построение — один запрос к модели («не более 8 концепций», «пиши компактно, чтобы уместиться в лимит токенов»). Нет программы курса (оглавление учебника, дескрипторы CEFR), поэтому состав зависит от прогона: в одном нет лексики, в другом нет времён.
3. **Связи формальные.** В графе из 13 узлов у 4 узлов нет ни одной исходящей связи, у двух корней по 3–5 исходящих; «предпосылки» выглядят как «после A идёт B», а не как «B невозможно понять без A».
4. **Курс — один шаблон на все узлы.** Каждый из 13 шагов — «прочитать → вспомнить → карточка», независимо от того, грамматика это, лексика или стратегия. Порядок идёт по глубине графа, поэтому он повторяет структуру ответа модели. «Применить» в цепочке нет вообще: цель «понять» не поднимается выше ступени understand. Нет объёма (сколько часов, сколько слов), нет повторения по спирали.
5. **Лексика и навыки смешаны с понятиями.** «Частотная лексика» — один узел, хотя это тысячи единиц, которые должны быть колодой карточек (T-0045), привязанной к уровню. «Стратегия экзамена» и «Структура эссе» — навыки, а не знания.

Корневая причина: **источником знаний служит память модели в одном запросе**. Модель честно отвечает «средним по интернету»: поверхностно и каждый раз по-разному.

## Предложение

Канон базовых предметов строится из проверенных учебников, загруженных куратором в PDF (математика, языки, программирование…).

1. **Источники.** Куратор загружает PDF учебника с метаданными: предмет, уровень, издание. Текст режется на фрагменты с номером страницы и заголовком главы (разбор PDF и фрагменты уже есть в `core/materials.py`).
2. **Структура из оглавления.** Оглавление и заголовки дают скелет: главы → темы. Модель не придумывает программу, а нормализует её в понятия.
3. **Теория из текста.** Для каждого понятия модель выделяет объяснение, примеры и частые ошибки *из конкретных фрагментов* и обязана ссылаться на их id (механизм «обязательная ссылка на фрагмент» уже работает для личных материалов). Понятие без ссылки не принимается.
4. **Проверка куратором.** Новые понятия — черновик с оценкой уверенности; в канон (общий для всех, `user_id = null`) попадают после подтверждения. Показываем источник: книга, страница.
5. **Связи.** Предпосылки берутся из порядка изложения в книге и от модели по паре понятий, а не из одного ответа на весь граф.
6. **Курс.** Тип шага зависит от типа понятия (грамматика, лексика, навык, процедура); лексика — колоды карточек по уровню; у шага есть объём и оценка времени.

## Не решено

- Права: чьи учебники можно загружать и хранить (лицензии). Копирование чужого текста в теорию узла и показ его учащимся — отдельный вопрос; безопасный вариант — хранить фрагменты как источник и показывать собственное изложение с номером страницы.
- Разбор сложных PDF: формулы (математика), таблицы, сканы без текстового слоя.
- Сколько понятий на главу и как выделять «понятие» в процедурном предмете (программирование).
- Нужен ли этап «задания из упражнений учебника» или упражнения генерируются.
