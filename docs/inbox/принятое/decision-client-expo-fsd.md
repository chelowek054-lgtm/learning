# Решение: Клиент на Expo/React Native по Feature-Sliced Design; ядро в `shared/engine`

Когда принято: 2026-07-04. Статус: принято.

## Зачем решали

Нужен один код на iOS и Android; команда знает TypeScript. Архитектура требует доменно-независимого ядра, а предметы подключаются модулями.

## Что решили

Клиент пишется на **Expo (React Native, TypeScript)** с expo-router. Код организован по **FSD**: `app → pages → widgets → features → entities → shared`.

Доменно-независимое ядро — типы Activity, реестр модулей, порты, FSRS — живёт в `src/shared/engine`: нижний слой FSD по определению не содержит бизнес-специфики. Остальное разложено так:

- метаданные модулей — `entities/module`;
- сборка манифестов с рендерерами — `widgets/module-registry`;
- рендереры — `features`.

`src/app` содержит только роуты, потому что expo-router исполняет всё внутри этого каталога.

## Отвергнуто и почему

- **Flutter**: за — Производительность UI; против — Другой язык; команда сильнее в TS.
- **Модули как отдельные npm-пакеты**: за — Явные границы; против — Workspaces усложняют Expo; FSD даёт границы слоями.

## Последствия

Пока не подключён линтер (P3-CI-04), границы слоёв держатся на ревью и grep. Состояние хранится в React context (`entities/session`, провайдер реестра). Zustand и TanStack Query из исходного плана не понадобились.
