# Задача: единый контракт модуля и реестр для платформы

## Зачем

Требование R-0027 (ядро платформы не знает предметов) и контракт C-0001 (манифест, жизненный цикл, версии) пока без работы, которая их выполняет. Это первый шаг перехода к платформе из фазы P-0015 и его основа: пока нет одного контракта, граф, данные и способы запоминания нельзя разделить честно.

## Что считается сделанным

- Серверный и клиентский манифесты сведены в одно описание модуля по контракту C-0001: идентификатор, версия, версия контракта ядра, что даёт, что просит.
- Ядро при подключении проверяет манифест и отказывает с понятной причиной на несовместимой версии, занятом идентификаторе, неизвестном запросе.
- Есть жизненный цикл: установка, включение, отключение, обновление, удаление; отключение не удаляет данные пользователя без явной команды; зависимости объявляются и не образуют цикла.
- Три базовых модуля (граф, повторение, письмо) подключаются по новому контракту без изменения поведения для учащегося.
- Решение A-0020 о платформе принято человеком до начала работы: задача опирается на него.

## Чего не делаем

- Не делаем контракт «на вырост» с десятками необязательных точек расширения: только то, что нужно трём базовым модулям.
- Не открываем подключение сторонних модулей: это отдельные задачи после изоляции и разрешений.

## Что мешает

- Не принято решение A-0020 (оно пока черновик) и не выяснено, где исполняются чужие модули: от этого зависит форма манифеста.
- Нет карты возможностей, которую меняет эта задача; нужна связь с M-0001 после уточнения.

## Не выяснено

- Формат манифеста: файл рядом с модулем, запись в реестре или оба.
- Нужна ли подпись и проверка целостности модуля до подключения.
