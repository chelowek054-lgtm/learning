# Речь (Speaking)

## Зачем

Закрыть последний тип продукции — устную речь — тем же циклом, что и письмо: ответ → оценка по рубрике → разбор → ошибки в повторение.

## Состояние

черновик

## Как должно вести себя

1. Учащийся открывает `speaking_response`: видит задание (IELTS Speaking Part 1/2/3) и, для Part 2, время на подготовку.
2. **Запись офлайн** (`expo-audio`): запрос разрешения на микрофон; старт/стоп; длительность; прослушивание своей записи до отправки; перезапись.
3. **Отправка.** Запись сохраняется на устройстве, создаётся `response` (ссылка на файл) и job `transcribe`. При сети файл загружается multipart и привязывается к `response`. После успешной загрузки файл удаляется с устройства.
4. **Распознавание** — отложенная задача: аудио + язык → текст + тайминги слов. Длинная, тихая или пустая запись даёт понятную ошибку, а не пустую оценку.
5. **Оценка** — job `grade_speaking` по рубрике `ielts_speaking` v1: Fluency & Coherence, Lexical Resource, Grammatical Range & Accuracy, Pronunciation → band 0–9. Темп и паузы считаются из таймингов. Произношение по тексту STT честно не оценить: у критерия Pronunciation в разборе стоит пометка об ограничении, пока нет провайдера с оценкой сигнала.
6. **Error-log**: ошибки речи становятся карточками тем же путём, что ошибки письма.
7. **Хранение** записей на сервере — по политике P4-PRIV-01 (по умолчанию удаление после оценки).

## Что система обязана обеспечить

- Учащийся записывает устный ответ офлайн и прослушивает его до отправки. Признак: Запись создаётся и воспроизводится без сети. (Сейчас: принято, не начато; прежний номер — FR-SPK-01.)
- Запись уходит на backend при сети; есть пределы размера и длительности. Признак: Запись сверх лимита отклоняется с понятной причиной. (Сейчас: принято, не начато; прежний номер — FR-SPK-02.)
- Речь распознаётся отложенной задачей; без ключа работает заглушка. Признак: Job `transcribe` → текст с таймингами. (Сейчас: принято, не начато; прежний номер — FR-SPK-03.)
- Ответ оценивается по рубрике IELTS Speaking; ограничение оценки произношения показано честно. Признак: Разбор по 4 критериям; у Pronunciation есть пометка об ограничении. (Сейчас: принято, не начато; прежний номер — FR-SPK-04.)
- Ошибки речи попадают в SRS тем же error-log. Признак: После разбора есть карточки `source='error_log'` из речи. (Сейчас: принято, не начато; прежний номер — FR-SPK-05.)
- Записи голоса хранятся по принятой политике и удаляются по ней. Признак: Запись удаляется с устройства после отправки, с сервера — по политике. (Сейчас: принято, не начато; прежний номер — FR-SPK-06.)

## Что считается сделанным

- Запись создаётся и прослушивается без сети — проверка: device; сейчас: не сделано. (прежний номер AC-14.1)
- При сети запись загружается и удаляется с устройства — проверка: device; сейчас: не сделано. (прежний номер AC-14.2)
- Без ключа STT пайплайн работает на `MockSTT` — проверка: test; сейчас: не сделано. (прежний номер AC-14.3)
- Пустая или слишком тихая запись → понятная ошибка, а не оценка — проверка: test; сейчас: не сделано. (прежний номер AC-14.4)
- Разбор: 4 критерия, `overall`, ошибки; у Pronunciation есть пометка ограничения — проверка: live; сейчас: не сделано. (прежний номер AC-14.5)
- Ошибки речи стали карточками `error_log` — проверка: live; сейчас: не сделано. (прежний номер AC-14.6)
- Запись на сервере удаляется по политике — проверка: test; сейчас: не сделано. (прежний номер AC-14.7)
- Ключи STT только на backend — проверка: grep (NFR-02); сейчас: не сделано. (прежний номер AC-14.8)

## Что мешает

- Клиент проверен на устройстве (Ф3); политика хранения голоса принята (P4-PRIV-01)

## Не выяснено

1. Где STT: провайдер по API, `faster-whisper` в контейнере, on-device. Влияет на приватность, стоимость, офлайн → ADR (P4-WS2-00).
2. Оценка произношения: ограничить критерий или искать провайдера с оценкой сигнала.
3. Приватность голоса: голос — биометрия; политика строже, чем для текста (P4-PRIV-01).
4. Фоновая обработка: STT не укладывается в синхронную обработку на `/sync/push` (SPEC-03).
