# Задача: единое хранилище данных пользователя с доступом по разрешениям

## Зачем

Требование R-0031: данные учащегося принадлежат платформе, а не модулям. Хранит их отдельный модуль, остальные получают доступ через него по разрешениям. Тогда человек меняет способ запоминания и не теряет накопленное. Задача входит в фазу P-0015.

## Что считается сделанным

- Все данные пользователя лежат в одном хранилище с единым журналом событий; модуль не заводит собственных таблиц с личными данными в обход него.
- У каждого типа данных описаны владелец, назначение и срок хранения.
- Модуль получает только объявленные в манифесте и разрешённые человеком типы данных, чтение и запись разрешаются отдельно.
- Любой доступ модуля пишется в журнал, который человек может прочитать.
- Человек может отозвать разрешение, выгрузить свои данные целиком и удалить их; удаление доходит и до того, что модуль успел запросить.
- Офлайн-режим сохраняется: локальное хранилище остаётся источником правды для действий.

## Чего не делаем

- Не отдаём модулю «весь профиль» по умолчанию и не смешиваем данные разных людей в одном ответе.

## Что мешает

- Не написана политика данных: без неё нельзя описать владельца и срок каждого типа.
- Данные сейчас размазаны: ответы, карточки и освоенность лежат в разных таблицах и пишутся разными частями системы.
- Голос — биометрия, правила его хранения нужно решить до первой записи.

## Не выяснено

- Модель разрешений: список типов данных при установке модуля или постоянная настройка.
- Кому принадлежат производные данные модуля (например, рекомендации).
- Формат выгрузки, пригодный для переноса в другую систему.
