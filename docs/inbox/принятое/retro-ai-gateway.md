# Выполнено: AI-gateway — транспорт, учёт токенов, кэш, рубрики при старте

## Зачем

Оформить задачей работу по требованию R-0004, которая уже сделана и проверена. Это не новая разработка: описано то, что есть в коде, со ссылками на пройденные проверки.

## Что считается сделанным

- Провайдер LLM задаётся конфигурацией (адрес, ключ, модели), реализация одна на любой OpenAI-совместимый сервис; без ключа работает детерминированная заглушка. Решение — A-0009.
- Транспорт повторяет обрыв канала, ответ «не хватает кредита» (с подстройкой бюджета) и ответ текстом вместо вызова инструмента; лимит токенов передаётся в каждом запросе.
- Расход токенов учитывается на каждый ответ провайдера, включая оплаченные неудачные, по пользователю и назначению; сводка за период доступна только администратору; сбой учёта не ломает вызов.
- Детерминированные ответы (оценка по рубрике, оценка открытого ответа) кэшируются по хэшу входа; построение графа и его рост не кэшируются, «перестроить» даёт новый результат.
- Рубрики версионируются; недостающие добавляются при старте API без перезаписи существующих версий; на чистой базе после миграций рубрики появляются без ручного сида.

## Что уже есть в коде

`core/ai_gateway` (транспорт и заглушка), `core/usage.py` и `core/routers/usage.py` (учёт и сводка), `core/llm_cache.py` (кэш), `core/modules.py` (добавление рубрик при старте), миграции 0009 и 0012. Слито в `main` (learningBack PR 1).
