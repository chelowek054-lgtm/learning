# Решение: графовая СУБД — PostgreSQL + Apache AGE + pgvector (предложение)

Требования: открытая лицензия; сотни тысяч понятий и миллионы связей; транзакции вместе с остальными данными (пользователи, освоенность, курсы); обход предпосылок; векторный поиск для слияния; один небольшой сервер.

## Варианты

| Вариант | Лицензия | За | Против |
|---|---|---|---|
| **PostgreSQL + Apache AGE + pgvector** | Apache 2.0 / PostgreSQL | одна база и одна транзакция с остальными данными; Cypher (openCypher) в Postgres; pgvector рядом; без синхронизации двух хранилищ | AGE моложе Neo4j; версия AGE привязана к версии Postgres (1.7 — PG 17 и 18, 1.8 — только PG 18); у нас PG 16 |
| Neo4j Community | GPLv3 | самый зрелый, лучшие инструменты | отдельный сервер и синхронизация с Postgres; нет кластеризации и ролей в Community |
| NebulaGraph, JanusGraph | Apache 2.0 | масштаб | избыточны и тяжелы для нашего размера |
| ArangoDB, Memgraph, FalkorDB | BSL / SSPL | — | не открытые лицензии |
| Kùzu | MIT | встраиваемый, быстрый | репозиторий заархивирован в октябре 2025 |

## Предложение

PostgreSQL 17 + Apache AGE + pgvector. Таблицы `concept`, `concept_edge`, `domain_edge` остаются источником правды на переходе; AGE добавляется для обходов и Cypher, pgvector — для кандидатов на слияние. Отдельную графовую базу брать только если обходы в AGE окажутся узким местом по замеру.

## Не выяснено

- Замер обходов на реальном размере графа до окончательного принятия решения.
