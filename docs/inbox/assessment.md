# Задания из теории узла

## Зачем

Порождать проверку понимания не «из воздуха», а из теории конкретного узла: меньше галлюцинаций, воспроизводимость, дистракторы из реальных заблуждений.

## Состояние

реализовано (test + live на RouterAI)

## Как должно вести себя

1. Запрос задания задаёт узел, ступень Блума и форму:
   - `test` — `remember`, `understand` (вспомнить и объяснить);
   - `practice` — `apply`, `analyze`, `evaluate`, `create` (применить и создать);
   - `probe` — любая ступень, одиночный зонд плейсмента.
   Недопустимая пара ступень/форма → 422.
2. **Отсев.** Узел без пригодной теории (только summary, без разделов) → 409: по заголовку задание не строится.
3. **Кэш.** Ключ `(concept_id, concept_version, bloom, kind)`. Есть в кэше — отдаётся без LLM. Нет — генерируется (по 3 задания), сохраняется, строки прошлых версий узла удаляются.
4. **Генерация.** Промпт содержит summary, разделы, примеры, контрпримеры и источники узла. Без ключа — детерминированные задания: заблуждения становятся дистракторами, примеры — практикой.
5. **Оценка ответа.** Закрытый вопрос (варианты) проверяется локально по отмеченному верному варианту. Открытый — роль `estimate_mastery`: LLM сравнивает с эталоном из узла и возвращает `score` 0..1 и объяснение. Без ключа — доля совпадения слов с эталоном (порог 0.5).

## Что система обязана обеспечить

- Задания генерируются из теории узла по ступени Блума и форме (`test`/`practice`/`probe`); узлы без теории отсекаются. Признак: Промпт содержит теорию узла; узел-ярлык → 409. (Сейчас: реализовано; прежний номер — FR-ASM-01.)
- Задания кэшируются по `(узел, версия, ступень, форма)`; правка теории их обесценивает. Признак: Повторный запрос из кэша; новая версия узла → новые задания, старые строки удалены. (Сейчас: реализовано; прежний номер — FR-ASM-02.)
- Ответ оценивается: закрытый вопрос локально по вариантам, открытый — LLM по эталону из узла. Признак: Закрытый не вызывает LLM; открытый возвращает `score` 0..1 и объяснение. (Сейчас: реализовано; прежний номер — FR-ASM-03.)
