# Движок Activity и модульная система

## Зачем

Дать один примитив, **Activity**, через который проходит любое учебное взаимодействие, и способ подключать предметы модулями, не трогая ядро (vision).

## Состояние

реализовано (2026-09-30)

## Как должно вести себя

1. При старте клиента composition root собирает манифесты всех модулей и регистрирует их в реестре ядра.
2. Экран получает Activity и просит у реестра рендерер по `activity.type`. Если рендерера нет, показывается плейсхолдер `NotImplementedActivity`.
3. Название и подсказку типа экран берёт из реестра (`getActivityTitle`). Незнакомый тип отображается своим слугом: это заметно и лучше пустоты.
4. Рендерер завершает Activity вызовом `onComplete(draft)`. Запись ответа в лог и постановку задач делает не ядро, а feature через `shared/api`.
5. Если тип объявил офлайн-грейдер, feature вызывает его сразу и показывает черновой сигнал.
6. На backend модуль подключается через `core.modules` (ADR-0019): роутер, рубрики, типы оцениваемых jobs, провижининг по предмету и представления админки. Ядро вызывает их по реестру, не зная имён модулей.

## Что система обязана обеспечить

- Любое учебное взаимодействие представлено Activity с полями `module`, `type`, `connectivity`, `payload`. Признак: Все экраны заданий получают Activity и ничего больше. (Сейчас: реализовано; прежний номер — FR-ENG-01.)
- Модули регистрируются манифестом; ядро диспетчеризует по `type` табличным поиском. Признак: Повторная регистрация модуля и коллизия типов между модулями отклоняются с ошибкой. (Сейчас: реализовано; прежний номер — FR-ENG-02.)
- Название и подсказка типа Activity для человека берутся из реестра, а не из экранов. Признак: Ни один экран не держит свою карту `type → название`. (Сейчас: реализовано; прежний номер — FR-ENG-03.)
- Тип без рендерера показывается плейсхолдером, а не падением. Признак: Activity нереализованного типа открывается и объясняет, что тип ещё не поддержан. (Сейчас: реализовано; прежний номер — FR-ENG-04.)
- Модуль может объявить офлайн-грейдер, дающий черновой сигнал без сети. Признак: `getLocalGrader(type)` возвращает функцию для типов, где он объявлен. (Сейчас: реализовано; прежний номер — FR-ENG-05.)
- Backend-модули регистрируются через общий контракт, а ядро backend не знает их имён. Признак: В `learningBack/core` нет импорта `modules.*` и строк с именами модулей. (Сейчас: реализовано; прежний номер — FR-ENG-06.)
