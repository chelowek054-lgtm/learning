# Требование: поиск источников и разбор их в граф

Для областей, где в графе нет или мало знаний:

1. **Поиск источников.** Модель с веб-поиском составляет список: учебники, курсы, документация. Приоритет — разрешённые открытые источники (OpenStax, LibreTexts, Wikibooks, Project Gutenberg, arXiv, официальная документация языков и библиотек), затем остальное (границы — в «Решении: правила использования источников»).
2. **Загрузка в объектное хранилище** (см. «Решение: объектное хранилище») с метаданными: откуда, когда, лицензия (если известна), кто и по какому запросу.
3. **Разбор.** Документ режется на фрагменты (страница, глава; парсер PDF и фрагменты уже есть в `core/materials.py`). Модель выделяет понятия, объяснения, примеры, частые ошибки и связи; **каждое утверждение — со ссылкой на фрагмент**. Без ссылки не принимается.
4. **Слияние.** Новое понятие сравнивается с существующими: кандидаты по векторной близости (pgvector), решение модели — «то же / уточнение / новое / противоречит». Совпадения сливаются (у понятия несколько источников), противоречия помечаются для специалиста. Слияние идёт «на основе логичности данных»: порядок изложения, согласованность определений, отсутствие циклов предпосылок.
5. Всё внесённое получает статус «черновик от LLM» (см. «Требование: статус черновика и уведомление человека»).

## Критерии готовности

- Разбор книги выполняется один раз на книгу (не на человека), в фоне воркером; повтор по уже разобранной книге ничего не делает.
- Каждое понятие и каждая связь хранят список источников (документ, страница, фрагмент) и признак «подтверждено / нет».
- Можно удалить источник вместе со всем, что выведено только из него.
- Лимит документов и токенов на один запрос человека.

## Не выяснено

- Провайдер веб-поиска (см. «Решение: провайдер веб-поиска»).
- Формулы, таблицы и сканы без текстового слоя: отдельный разбор (OCR, формулы), особенно для математики.
