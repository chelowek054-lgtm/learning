# Решение: карточки повторения с нескольких устройств сливаются по последнему ревью

## Выбор

Состояние карточки повторения, пришедшее с разных устройств, сливается по последнему ревью, а не по времени записи на сервер. Побеждает состояние с более поздним `last_review`; при равном времени — с большим числом повторов, затем с большим числом провалов; равные состояния повторно не принимаются. Правило одно на сервере (`core/srs.py`) и на клиенте (`card-merge.ts`). Проигравшая версия подтверждается без записи, победившая приезжает на устройство при следующей синхронизации. Ответы (`response`) остаются неизменяемыми и конфликтов не дают.

## Почему

Устройство, которое повторяло карточку вчера, но синхронизировалось сегодня, не должно откатывать интервал, выставленный другим устройством позже. Время записи отражает порядок синхронизации, а не порядок обучения.

## Отвергнуто

- Слияние по времени записи (прежнее поведение): откатывает интервалы, если устройства синхронизируются в другом порядке, чем повторяли.
- Слияние по журналу всех ревью с пересчётом состояния: точнее, но требует хранить и передавать журнал повторений; для текущего размера данных избыточно.

## Последствия

Если два устройства повторили одну карточку независимо, учитывается только более позднее ревью: промежуточное повторение с более раннего устройства в состоянии карточки теряется (сам ответ в журнале остаётся). Для точного учёта придётся перейти на слияние по журналу ревью.
