# Аккаунт, вход, восстановление, роли

## Зачем

Отделить данные одного учащегося от другого и дать администратору права на курирование канона, без внешнего провайдера авторизации.

## Состояние

частично — механика готова; доставка кода и ужесточение под публичный доступ — Ф6

## Как должно вести себя

1. **Регистрация.** Email и пароль от 6 символов. Сервер создаёт пользователя, выполняет провижининг стартового контента (SPEC-05) и сразу выдаёт токен.
2. **Вход.** Верная пара → токен. На неверную пару один ответ, без уточнения, что именно неверно.
3. **Сессия** — Bearer JWT (HS256, срок из конфига, по умолчанию 30 дней). Клиент хранит его в SecureStore (web — в `localStorage`). На `login`/`register` заголовок `Authorization` не отправляется.
4. **Профиль** — произвольный JSON. Клиент кладёт туда `subject` (SPEC-12).
5. **Восстановление пароля.** Запрос кода гасит прежние невыданные коды и создаёт новый (8 цифр, TTL из конфига). Ответ одинаков для существующего и несуществующего email. Подтверждение проверяет код за постоянное время, считает неверные попытки и после лимита отвечает 429. Пока доставки нет, код читается из БД.
6. **Роль администратора** (`is_superuser`) выдаётся только CLI. Эндпоинты курирования требуют её (`CurrentSuperuser`).
7. **Ошибки сети** клиент отличает от ошибок API: «нет связи» не выдаётся за «неверный пароль».

## Что система обязана обеспечить

- Учащийся регистрируется по email и паролю (от 6 символов) и сразу получает сессию. Признак: `POST /auth/register` → 201 + токен; повторный email → 409. (Сейчас: реализовано; прежний номер — FR-AUTH-01.)
- Учащийся входит по email и паролю. Признак: Верная пара → токен; неверная → 401 без уточнения, что именно неверно. (Сейчас: реализовано; прежний номер — FR-AUTH-02.)
- Учащийся читает и меняет свой профиль (предмет, цель). Признак: `GET /auth/me`, `PUT /auth/me/profile`. (Сейчас: реализовано; прежний номер — FR-AUTH-03.)
- Учащийся восстанавливает пароль одноразовым кодом из 8 цифр с ограниченным сроком и числом попыток. Признак: Код действует TTL; после лимита попыток → 429; ответ на запрос не раскрывает, есть ли такой email. (Сейчас: реализовано; прежний номер — FR-AUTH-04.)
- Код восстановления доставляется на почту. Признак: Код приходит письмом; в БД хранится только хеш. (Сейчас: принято, не начато; прежний номер — FR-AUTH-05.)
- Роль администратора выдаётся только из CLI. Признак: `scripts.createsuperuser` создаёт или повышает пользователя; через API роль не получить. (Сейчас: реализовано; прежний номер — FR-AUTH-06.)
- После смены пароля прежние сессии недействительны; запрос кода ограничен по частоте. Признак: Старый токен → 401 после смены пароля; частые запросы кода → 429. (Сейчас: принято, не начато; прежний номер — FR-AUTH-07.)
