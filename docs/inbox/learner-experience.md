# Опыт учащегося: онбординг, «Сегодня», язык интерфейса

## Зачем

Интерфейс говорит от задачи человека, а не от модели системы: человек всегда знает, что делать сейчас и зачем (personas).

## Состояние

частично — всё, кроме экрана прогресса, готово (live web)

## Как должно вести себя

1. **Онбординг** (после регистрации, пока не выбран предмет): поле «что изучаете» (свободный текст) и целевой уровень из четырёх формулировок. Сохраняется в `profile.subject = {id: slug(title), title, target}`. Slug сохраняет юникод; в URL он кодируется слоем `api`.
2. **Предмет** читается экранами через `useSession().subject`; строк вида `'ml'` в экранах нет.
3. **«Сегодня»** показывает **одно** действие с причиной. Приоритет (`nextAction`):
   1. нет предмета → выбрать предмет;
   2. есть текущий шаг курса → шаг, причина из `StepReason`;
   3. есть карточки к повторению → повторение;
   4. иначе → плейсмент.
   Сырой список активностей вынесен на служебный роут `/activities`.
4. **Словари** — единственные источники: названия типов (`ActivityTypeDef.title/hint`), уровни (`MASTERY_TARGETS`), причины шагов (`STEP_REASON`). Новый экран спрашивает словарь, а не заводит свою карту.
5. **Граф**: учащийся видит карту на чтение (`GraphMap`), администратор — курирование (`GraphCuration`); выбор по `isAdmin`. Пустая карта предлагает построить себя (ADR-0016); узлы `draft` помечены «не проверено».
6. **Тема**: системная, светлая или тёмная. Все цвета, кегли и отступы — в `shared/config/design.ts`.
7. **Прогресс** (цель, `FR-UX-07`): экран с метриками из metrics.md — удержание, рост по рубрикам, положение границы относительно цели.

## Что система обязана обеспечить

- Онбординг спрашивает предмет и целевой уровень формулировками человека. Признак: `profile.subject = {id, title, target}`; предмет с кириллицей работает во всех запросах. (Сейчас: реализовано; прежний номер — FR-UX-01.)
- Экран «Сегодня» предлагает ровно одно следующее действие и объясняет причину. Признак: Приоритет: выбор предмета → шаг курса → повторение → плейсмент. (Сейчас: реализовано; прежний номер — FR-UX-02.)
- Интерфейс не показывает внутренние метки системы (слуги типов, английские ступени, служебные поля). Признак: Названия типов, уровней и причин шагов берутся из единых словарей. (Сейчас: реализовано; прежний номер — FR-UX-03.)
- Тема: системная, светлая или тёмная; всё оформление в одном месте. Признак: Ни один файл, кроме `shared/config/design.ts`, не объявляет цвет. (Сейчас: реализовано; прежний номер — FR-UX-04.)
- Учащийся видит карту графа на чтение; администратор — инструменты курирования. Признак: Кнопки курирования не показываются учащемуся. (Сейчас: реализовано; прежний номер — FR-UX-05.)
- Восстановление пароля доступно из клиента: запрос кода → ввод кода → новый пароль. Признак: Сценарий проходит в клиенте без обращения к API вручную. (Сейчас: реализовано; прежний номер — FR-UX-06.)
- Учащийся видит свой прогресс: метрики из [metrics.md](../00-product/metrics.md). Признак: Экран прогресса показывает удержание, рост по рубрикам и положение границы. (Сейчас: принято, не начато; прежний номер — FR-UX-07.)
