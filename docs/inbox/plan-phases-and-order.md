# План реализации: порядок и критерии этапов

## Зачем

Зафиксировать порядок работ: что блокирует что и по чему поймём, что этап завершён.

## Этапы

- **Ф0 — Каркас** — цель: Связный запускаемый скелет: суперпроект, FSD-клиент, ядро, FastAPI+Postgres. Этап завершён, когда: Клиент показывает зарегистрированные типы; backend отвечает; БД мигрируется. (Сейчас: ✅ 34/34.)
- **Ф1 — MVP** — цель: Вертикальный срез главной гипотезы: письмо с AI-оценкой + SRS + ML-трек, offline-first. Этап завершён, когда: Сквозной сценарий эссе → оценка → карточки → повторение. (Сейчас: частично 31/33 · 2 переоткрыты → Ф3.)
- **Ф2 — Модель знаний** — цель: Граф понятий, задания из теории, плейсмент, курс, замкнутая петля. Этап завершён, когда: Граф → плейсмент → курс → шаг → ответ → сдвиг границы. (Сейчас: ✅ 30/30.)
- **Ф3 — Укрепление** — цель: Устройство, CI, инварианты, sync, стоимость LLM, долги графа. Этап завершён, когда: Клиент проверен на устройстве; CI зелёный; инварианты проверяются автоматически; расхождения спек закрыты. (Сейчас: частично 14/29.)
- **Ф4 — Речь и рецепция** — цель: Speaking (запись → STT → рубрика), reading/listening офлайн, генерация материалов. Этап завершён, когда: Речь оценена и питает SRS; дриллы проходятся в самолётном режиме — **на устройстве**. (Сейчас: не сделано.)
- **Ф5 — Расширение обучения** — цель: Задачи на код, импорт PDF в граф, Task 1, TOEFL, языковой граф, экран прогресса. Этап завершён, когда: Оба первых предмета в полном объёме; прогресс виден учащемуся. (Сейчас: не сделано.)
- **Ф6 — Продукт и релиз** — цель: Политика данных, доставка кода, промоция узлов, мульти-девайс, деплой, сторы, монетизация. Этап завершён, когда: Приложение в сторах; прод с managed Postgres; политика данных исполняется. (Сейчас: не сделано.)

## Что мешает

- Речь (этап 4) нельзя честно сделать, пока клиент не проверен на устройстве: микрофон в web не проверить.
- Публичный релиз (этап 6) невозможен без политики данных и доставки кода восстановления.

## Что считается сделанным

- Все задачи этапа закрыты или отменены с причиной.
- Критерий выхода этапа выполнен и доказан: тест, живой прогон, сборка или запуск на устройстве — названо, каким именно.
- Документация сверена с кодом: в описаниях не осталось устаревших расхождений.
