Сверка новых утверждений с узлом и пул проблем для администраторов

Зачем: главное правило слияния — в узле нет расхождений. Проверять это нужно по утверждениям, а не по целым понятиям, и без лишних запросов к модели.

Что делаем:
- Слияние понятия: ближайшие по вектору во всём графе. Близость не ниже 0.92 и совпадающее нормализованное название — то же понятие без модели; от 0.6 до 0.92 — решает модель (решения кэшируются, как сейчас); ниже 0.6 — новое понятие. Пороги стартовые, подбираются на данных.
- Сверка утверждений: для узла, в который пришли новые утверждения, собирается один запрос в фиксированном формате: полный список принятых утверждений узла с номерами и рядом добавляемые утверждения. Модель для каждого добавляемого отвечает: «совпадает с №…», «нейтрально» или «противоречит №…» с коротким объяснением.
- Совпадает — к принятому утверждению добавляется ссылка на новый источник (растёт подтверждённость). Нейтрально — утверждение принимается как новое. Противоречит — создаётся проблема в пуле для администраторов: оба утверждения, их источники с цитатами, объяснение модели.
- Утверждение с открытой проблемой не попадает в теорию и задания, пока проблема не решена.
- Один запрос на узел на пачку добавлений, а не на каждую пару.

Пул проблем: список для администраторов и специалистов области; фильтр по области, источнику, давности. Решение — выбрать сторону, оставить обе с условиями применимости, пометить «спорно» или отклонить источник. Решение пишется в журнал и обратимо.

Готово, когда: добавление источника к узлу даёт ровно один запрос сверки на узел; противоречие появляется в пуле с обоими утверждениями и цитатами; спорное утверждение не видно учащемуся.
