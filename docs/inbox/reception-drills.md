# Чтение и аудирование

## Зачем

Закрыть рецептивные навыки экзаменационным форматом на время. Проверка детерминирована и работает без сети; разбор ошибок догоняет при сети.

## Состояние

черновик

## Как должно вести себя

**Reading-дрилл** (`reading_drill`, offline):

1. Passage и вопросы (MCQ, True/False/Not Given, заполнение пропуска) закэшированы на устройстве.
2. Таймер, навигация по вопросам, можно вернуться к вопросу до сдачи.
3. После сдачи локальный грейдер считает результат мгновенно: доля верных, время, верный ответ по каждому вопросу.
4. Ответ пишется в `response`; ставится job `explain_distractors`. Разбор «почему этот вариант неверен» приходит при сети и не мешает пройти дрилл.

**Listening-дрилл** (`listening_drill`, offline):

1. Аудио закэшировано; проигрывание без сети. Число прослушиваний ограничено (по умолчанию 1 — как на экзамене; настраивается).
2. Если аудио нет в кэше — понятное объяснение и предложение скачать при сети, а не пустой экран.
3. Проверка и результат — как у reading.

**Генерация материалов** (backend, модуль `languages`):

1. Passage + вопросы с дистракторами генерируются через `AIGateway.structured`; схема и промпт — в модуле.
2. Озвучка passage через порт `TextToSpeech` → аудио-материал.
3. Сгенерированный материал — `status='draft'` с `confidence`; администратор подтверждает в панели. Учащимся выдаются только `approved`.
4. Одинаковый вход генерации не оплачивается дважды (SPEC-04, FR-AI-06).

## Что система обязана обеспечить

- Администратор курирует сгенерированные учебные материалы (passages, аудио) так же, как узлы. Признак: Материал в статусе `draft` до подтверждения. (Сейчас: принято, не начато; прежний номер — FR-ADM-03.)
- Учащийся проходит reading-дрилл на время офлайн и сразу видит результат. Признак: В самолётном режиме дрилл проходится, результат мгновенный. (Сейчас: принято, не начато; прежний номер — FR-RCP-01.)
- Учащийся проходит listening-дрилл на закэшированном аудио с ограничением числа прослушиваний. Признак: Без сети аудио играет; при отсутствии в кэше — понятное объяснение. (Сейчас: принято, не начато; прежний номер — FR-RCP-02.)
- Разбор «почему этот вариант неверен» приходит при сети и не блокирует прохождение. Признак: Дрилл проходится без разбора; разбор догоняет после sync. (Сейчас: принято, не начато; прежний номер — FR-RCP-03.)
- Passages и аудио кэшируются на устройстве; повторный проход не требует сети. Признак: Повторное открытие дрилла без сети. (Сейчас: принято, не начато; прежний номер — FR-RCP-04.)
- Passages, вопросы с дистракторами и озвучка генерируются; результат курируется. Признак: Из темы получается passage с вопросами и аудио в статусе `draft`. (Сейчас: принято, не начато; прежний номер — FR-RCP-05.)

## Что считается сделанным

- Reading-дрилл проходится в самолётном режиме, результат мгновенный — проверка: device; сейчас: не сделано. (прежний номер AC-15.1)
- Listening играет закэшированное аудио без сети; лимит прослушиваний соблюдается — проверка: device; сейчас: не сделано. (прежний номер AC-15.2)
- Нет аудио в кэше — понятное объяснение — проверка: device; сейчас: не сделано. (прежний номер AC-15.3)
- Разбор дистракторов догоняет после sync; без него дрилл засчитан — проверка: live; сейчас: не сделано. (прежний номер AC-15.4)
- Из темы получается passage с вопросами и аудио в статусе `draft`; учащемуся он не выдаётся до `approve` — проверка: test; сейчас: не сделано. (прежний номер AC-15.5)
- Повторная генерация с тем же входом — из кэша — проверка: test; сейчас: не сделано. (прежний номер AC-15.6)

## Не выяснено

1. Число прослушиваний: экзаменационная строгость против пользы для обучения.
2. Где TTS: провайдер по API или заранее озвученный банк → ADR (P4-WS6-00).
3. Связь дриллов с графом знаний для языкового домена (SPEC-16, FR-KG-10).
