# AI-gateway, рубрики, стоимость

## Зачем

Держать все вызовы LLM в одной точке на backend: безопасность ключей, версионирование критериев, контроль стоимости, возможность сменить провайдера без правки кода.

## Состояние

частично — всё работает; остаётся решить судьбу неиспользуемого generate()

## Как должно вести себя

1. **Выбор реализации.** Есть `LLM_API_KEY` → `OpenAICompatibleGateway`, нет → `MockAIGateway` с детерминированными ответами. Модули спрашивают `has_llm()`, а не переменную окружения.
2. **Оценка по рубрике** (`grade`): рубрика берётся из БД (последняя версия или конкретная), промпт = шаблон рубрики + задание из `payload` + ответ. Модель — `rubric.model`, если задана, иначе `LLM_MODEL_SCORING`. Результат запрашивается вызовом инструмента `submit_grade` по `GRADE_JSON_SCHEMA`, дополняется `rubricId` и `rubricVersion`.
3. **Структурированный вызов** (`structured(tool, description, schema, prompt)`) — доменно-нейтральный. Схемы и промпты предметов живут в модулях (граф, задания, оценка ответа).
4. **Транспорт** повторяет запрос до 3 раз: обрыв канала; 402 (бюджет подстраивается под остаток кредита); ответ текстом вместо вызова инструмента. `max_tokens` передаётся всегда.
5. **Кэш** (`llm_cache`, ключ — sha256 от модели, инструмента, схемы и промпта). Включается явно (`cache=True`) только там, где ответ детерминирован по входу: оценка по рубрике и оценка открытого ответа. Граф и рост графа не кэшируются: «перестроить» даёт новый результат. Задания по узлу кэшируются отдельно (SPEC-09). Сбой кэша — промах, а не ошибка.
6. **Учёт**: каждый ответ провайдера, включая оплаченные неудачные попытки, пишет `llm_usage` (пользователь из Bearer-токена запроса, назначение — инструмент, модель, токены). Сбой учёта не ломает вызов. `GET /usage/summary` (администратор) — расход по пользователю и назначению за период.
7. **Рубрики на свежей базе**: API при старте добавляет недостающие рубрики модулей (insert-if-absent, `(id, version)` не перезаписываются); без БД API всё равно стартует.

## Что система обязана обеспечить

- Все вызовы LLM идут через единую точку backend; провайдер задаётся конфигурацией. Признак: Смена провайдера — правка `LLM_BASE_URL`/`LLM_API_KEY`/слагов без правки кода. (Сейчас: реализовано; прежний номер — FR-AI-01.)
- Без ключа система работает на детерминированной заглушке. Признак: Пустой `LLM_API_KEY` → `MockAIGateway`; все сценарии проходят. (Сейчас: реализовано; прежний номер — FR-AI-02.)
- Результат LLM структурирован по JSON-схеме и валидируется. Признак: Ответ модели вне схемы не попадает в БД; ответ текстом вместо вызова инструмента повторяется. (Сейчас: реализовано; прежний номер — FR-AI-03.)
- Рубрики версионированы и хранятся как данные; оценка помнит версию рубрики. Признак: Новая версия рубрики не требует релиза клиента; `grade.rubricVersion` заполнен. (Сейчас: реализовано; прежний номер — FR-AI-04.)
- Расход токенов учитывается по пользователю и типу задачи. Признак: Есть запрос «токены за период по пользователю и типу». (Сейчас: реализовано; прежний номер — FR-AI-05.)
- Повторная детерминированная генерация не оплачивается дважды. Признак: Одинаковый вход генерации отдаётся из кэша. (Сейчас: реализовано; прежний номер — FR-AI-06.)
- Рубрики доступны на любой базе без ручного seed. Признак: Свежая база после `alembic upgrade head` оценивает эссе. (Сейчас: реализовано; прежний номер — FR-AI-07.)
