# Построение графа цели из субдоменов: дерево достижения, как наука в Civilization

## Зачем

Сейчас модель строит граф области одним запросом (до 20 узлов). Большая цель так не строится: качество падает, граф получается плоским, и нет способа подключить уже готовые куски. Цель должна раскладываться в дерево достижения: крупная область делится на субдомены, субдомены — на примитивные области, из которых собирается итоговый граф. Возможность в функциональной карте — «Построение графа области».

## Что считается сделанным

- По подтверждённой формулировке цели модель предлагает разбиение на субдомены (например, «машинное обучение» → линейная алгебра, вероятности, оптимизация, модели, практика) и показывает его человеку для правки.
- Каждый субдомен строится отдельным запросом как собственный граф области; глубина разбиения ограничена, примитивная область — та, которую можно построить за один запрос.
- Итоговый граф цели — объединение графов субдоменов со связями-предпосылками между ними; порядок «что нужно знать до чего» сохраняется через границы субдоменов.
- Построенный граф остаётся черновиком до проверки куратором (как сегодня): сгенерированное моделью не выдаётся за проверенное.
- Если субдомен уже построен раньше, он не строится заново, а подключается (см. отдельную заметку про переиспользование).
- Расход токенов на построение виден и ограничен: цель не должна вылиться в сотни запросов без предупреждения.

## Чего не делаем

- Не строим весь граф одним запросом, как сейчас, для больших целей.
- Не принимаем разбиение молча: человек видит субдомены до построения.

## Что мешает

- Нужны правила, какую долю узлов можно строить без проверки куратором и как помечать непроверенные ветви.
- Граф знаний пока завязан на одну область (`domain`); цель из нескольких субдоменов требует понятия «цель» поверх областей — это решение для контракта модуля графов.

## Не выяснено

- Как выбирать глубину разбиения: по числу узлов, по размеру ответа модели или вручную.
