# Решение: переход PostgreSQL 16 → 17 с расширениями AGE и pgvector

Нужен для графовой СУБД (см. «Решение: графовая СУБД»): Apache AGE 1.7 поддерживает PG 17 и 18, а у нас PG 16.

## План

- Свой образ Postgres 17 с AGE и pgvector в `docker-compose` (staging и локально).
- Миграция данных: резервная копия `pg_dump`, проверка восстановления (скрипты `backup-db.sh` и `restore-check.sh` уже есть), накат в новую версию, сверка числа таблиц и версии миграций.
- Миграция Alembic, создающая расширения и схему графа; существующие таблицы не трогаются.
- Откат: копия до перехода, прежний образ.

## Не выяснено

- Окно простоя для staging и продуктива (сейчас продуктива нет — самое дешёвое время для перехода).
- Выбрать ли PG 18 сразу, учитывая, что AGE 1.8 поддерживает только его.
