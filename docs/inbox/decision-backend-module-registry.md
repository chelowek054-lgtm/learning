# Решение: Реестр модулей backend: ядро не знает модулей

Когда принято: 2026-09-30. Статус: принято.

## Зачем решали

Инвариант №3 требует доменно-независимого ядра, но сверка 2026-09-30 показала нарушение на backend: `core/app.py` импортировал роутер модуля знаний, `core/admin.py` — его представления, `core/provisioning.py` — генераторы `languages` и сам создавал демо-активности `languages`/`ml`, а `core/jobs.py` держал карту `grade_writing → languages`. Добавление нового модуля (например, `ielts_speaking` в Ф4) требовало бы править ядро.

## Что решили

1. Модуль — пакет, который экспортирует объект `backend`, наследник `core.modules.BackendModule`. Контракт, всё необязательное:
   - `router()` — свои эндпоинты;
   - `rubrics()` — рубрики-оценщики;
   - `grade_jobs()` — типы jobs, оцениваемых по рубрике, → модуль карточек для error-log;
   - `provision(session, user_id, subject, now)` — стартовый контент под предмет, идемпотентно;
   - `admin_views()` — представления таблиц для админки.
2. Какие модули подключены, задаёт конфиг `INSTALLED_MODULES` (по образцу `INSTALLED_APPS`). Ядро подгружает их через `importlib` и обращается только к контракту.
3. **Рубрики** сидятся при старте API по принципу *insert-if-absent*: существующая пара `(id, version)` не перезаписывается. Правка промпта — новая версия, иначе старые оценки потеряли бы смысл (NFR-06). Если БД недоступна, API всё равно стартует.
4. **Стартовый контент** создаётся не при регистрации, а при сохранении `profile.subject`: только тогда известно, что изучает человек. Каждый модуль сам решает, его ли это предмет (языковой — AWL и пробное эссе; ML — пробные задания). Предмет без подходящего модуля стартового контента не получает.

## Отвергнуто и почему

- **Оставить прямые импорты**: за — Просто; против — Нарушает NFR-03; каждый модуль правит ядро.
- **Python entry points (`pyproject`)**: за — Стандартный механизм; против — Нужна установка пакета; избыточно для монорепо-модулей.
- **Конфиг `INSTALLED_MODULES` + `importlib`**: за — Без установки; список явный и виден в конфиге; против — Имена пакетов в конфиге.

## Последствия

- Добавление модуля — пакет `modules/<имя>/` и строка в `INSTALLED_MODULES`; ядро не трогается.
- Инвариант проверяется `scripts/check-invariants.sh` и тестом `test_core_does_not_know_modules`.
- Эвристика «языковой/ML-предмет» — регулярное выражение по названию; она грубая и заменится выбором предмета из каталога (Ф5, P5-LANG-01).
- `scripts/seed.py` остаётся демо-инструментом и может импортировать модули напрямую (он вне `core/`).
