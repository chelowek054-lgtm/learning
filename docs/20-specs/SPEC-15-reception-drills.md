# SPEC-15 — Чтение и аудирование

| **Требования** | FR-RCP-01..05, FR-ADM-03, NFR-01 |

## Назначение

Закрыть рецептивные навыки экзаменационным форматом на время. Проверка детерминирована и работает без сети; разбор ошибок догоняет при сети.

## Поведение

**Reading-дрилл** (`reading_drill`, offline):

1. Passage и вопросы (MCQ, True/False/Not Given, заполнение пропуска) закэшированы на устройстве.
2. Таймер, навигация по вопросам, можно вернуться к вопросу до сдачи.
3. После сдачи локальный грейдер считает результат мгновенно: доля верных, время, верный ответ по каждому вопросу.
4. Ответ пишется в `response`; ставится job `explain_distractors`. Разбор «почему этот вариант неверен» приходит при сети и не мешает пройти дрилл.

**Listening-дрилл** (`listening_drill`, offline):

1. Аудио закэшировано; проигрывание без сети. Число прослушиваний ограничено (по умолчанию 1 — как на экзамене; настраивается).
2. Если аудио нет в кэше — понятное объяснение и предложение скачать при сети, а не пустой экран.
3. Проверка и результат — как у reading.

**Генерация материалов** (backend, модуль `languages`):

1. Passage + вопросы с дистракторами генерируются через `AIGateway.structured`; схема и промпт — в модуле.
2. Озвучка passage через порт `TextToSpeech` → аудио-материал.
3. Сгенерированный материал — `status='draft'` с `confidence`; администратор подтверждает в панели. Учащимся выдаются только `approved`.
4. Одинаковый вход генерации не оплачивается дважды ([SPEC-04](./SPEC-04-ai-gateway-and-rubrics.md), FR-AI-06).

## Контракт (проект)

`reading_drill.payload`: `{materialId, passage, questions: [{id, kind: mcq|tfng|gap, prompt, options?, answer}], timeLimitSec}`.

`listening_drill.payload`: `{materialId, audioMediaId, maxPlays, questions[], timeLimitSec}`.

`material` дополняется `status: draft|approved`, `confidence`, `media_id` для аудио. Порт `TextToSpeech.synthesize(text, voice, language) -> bytes`.

Кэш на устройстве: файлы аудио в `FileSystem.documentDirectory/media/`, ссылка из локальной таблицы `material`.

## Критерии приёмки

| AC | Критерий | Проверка | Статус |
|---|---|---|---|
| AC-15.1 | Reading-дрилл проходится в самолётном режиме, результат мгновенный | device | ⚪ |
| AC-15.2 | Listening играет закэшированное аудио без сети; лимит прослушиваний соблюдается | device | ⚪ |
| AC-15.3 | Нет аудио в кэше — понятное объяснение | device | ⚪ |
| AC-15.4 | Разбор дистракторов догоняет после sync; без него дрилл засчитан | live | ⚪ |
| AC-15.5 | Из темы получается passage с вопросами и аудио в статусе `draft`; учащемуся он не выдаётся до `approve` | test | ⚪ |
| AC-15.6 | Повторная генерация с тем же входом — из кэша | test | ⚪ |

## Открытые вопросы

1. Число прослушиваний: экзаменационная строгость против пользы для обучения.
2. Где TTS: провайдер по API или заранее озвученный банк → ADR (P4-WS6-00).
3. Связь дриллов с графом знаний для языкового домена ([SPEC-16](./SPEC-16-learning-expansion.md), FR-KG-10).
