## Назначение

Превратить работающий стенд в продукт, который можно дать людям: проверки на каждом изменении, продовое окружение, сторы, политика данных, работа с нескольких устройств.

## Поведение

### Проверки (Ф3)

1. **CI** на каждый push и PR в каждом из трёх репозиториев:
   - `learningBack`: `ruff format --check`, `ruff check`, `pytest` с сервисом Postgres;
   - `learningFront`: `npm run check` (typecheck, lint, format, tests, линтер границ FSD);
   - суперпроект: скрипт инвариантов (NFR-02, NFR-03, NFR-KG-1) и проверка ссылок в `docs/`.
2. **Устройство**: клиент запускается на iOS и Android (Expo Go на SDK 54, затем dev-client). Протокол прогона — в журнале ROADMAP.

### Окружения и деплой (Ф6)

| Окружение | Backend | БД | Клиент |
|---|---|---|---|
| dev | `docker compose` локально | Postgres в контейнере | Expo Go / web |
| staging | контейнер на хостинге | managed Postgres | EAS internal distribution |
| prod | контейнер на хостинге | managed Postgres, бэкапы | App Store / Google Play |

- Миграции применяются при деплое до старта нового API.
- Секреты — только из окружения хостинга; dev-значения (`dev-insecure-change-me`) запрещены в staging/prod — сервер отказывается стартовать.
- Выбор хостинга (Fly.io / Railway / VPS) и БД (Supabase / Neon) — ADR в P6-OPS-01.

### Релиз клиента (Ф6)

EAS Build для сторов, EAS Update для OTA-исправлений JS-части. Версия API (`/v1`) согласуется клиентом и backend; несовместимый клиент получает понятное сообщение об обновлении.

### Данные и приватность (Ф6, но политика голоса — до Ф4)

1. Документ `60-operations/data-policy.md`: какие данные хранятся, где, сколько, кто из провайдеров их видит (LLM, STT, TTS).
2. Сроки хранения исполняются кодом: периодическое удаление по `delete_after`.
3. Согласие с политикой при регистрации; версия принятой политики хранится у пользователя.
4. Удаление аккаунта удаляет все строки пользователя; агрегированная статистика — без идентификаторов.

### Несколько устройств (Ф6)

Стратегия конфликтов сверх LWW: для `srs_card` — слияние по последнему ревью (`fsrs_state.last_review`), а не по времени записи; для `response` конфликтов нет (иммутабелен). Решение — ADR в P6-SYNC-01.

### Монетизация (Ф6)

Модель — в `70-business/`; до решения требование в статусе `proposed`.
