# 20 — Спеки возможностей

Спека описывает **поведение и контракт** одной возможности настолько точно, чтобы по ней можно было написать код и тесты, а по коду — проверить спеку. Шаблон: [`_template.md`](./_template.md).

Спека опирается на требования (`10-requirements/`) и архитектуру (`30-architecture/`), но не повторяет их: устройство слоёв описано в архитектуре, здесь — только то, что видно снаружи возможности.

## Правила

1. **Спека раньше кода.** Задача плана, меняющая поведение, ссылается на спеку. Если спеки нет, сначала пишется спека со статусом `draft`.
2. **Критерий приёмки проверяем.** У каждого AC указано, чем он проверяется. AC «работает хорошо» не принимается.
3. **Раздел «Код» обязателен** для `partial` и `implemented`: по нему сверяют документ с реализацией.
4. **Расхождение — это задача.** Каждая строка в «Расхождениях» ссылается на задачу плана.
5. **Статус спеки** — `implemented`, только когда все AC 🟢 и расхождений нет.
