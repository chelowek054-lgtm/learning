# Глоссарий

Термины упорядочены по алфавиту: сначала латиница, затем кириллица. Если в коде термин называется иначе, чем в тексте, имя из кода указано в `моноширинном`.

| Термин | Значение |
|---|---|
| **AC** (acceptance criterion) | Критерий приёмки в спеке: `AC-<спека>.<n>`. Проверяется тестом или прогоном |
| **Activity** | Атомарная единица учебного взаимодействия: карточка, эссе, дрилл, зонд, шаг курса. Поля: `module`, `type`, `connectivity`, `payload` |
| **ADR** | Architecture Decision Record — запись решения: контекст, решение, последствия. Живут в `40-adr/` |
| **AIGateway** | Единая точка вызова LLM на backend (`core/ai_gateway`). Методы `grade`, `generate`, `structured` |
| **Assessment** | Задания, сгенерированные из теории узла (`kind`: `probe`/`test`/`practice`), закэшированные по версии узла |
| **AWL** | Academic Word List — стартовая колода академической лексики для модуля языков |
| **Bloom** (ступень Блума) | Уровень понимания: `remember` → `understand` → `apply` → `analyze` → `evaluate` → `create` |
| **Canon** (канон) | Общий кураторский граф предмета: `concept` и `concept_edge` |
| **Centrality** | Мера фундаментальности узла: доля узлов, транзитивно зависящих от него по `prereq`/`specializes` |
| **Connectivity** | Флаг типа Activity: `offline` (работает без сети) или `online` (нужен backend) |
| **COW** (copy-on-write) | Персональный слой графа поверх канона: канон читается напрямую, правка создаёт персональную строку поверх |
| **Core / derived** (тир) | `core` — фундаментальное ядро предмета, обязательное для любой цели; `derived` — ветви поверх ядра |
| **core-engine** | Доменно-независимое ядро. На клиенте `src/shared/engine`, на backend `learningBack/core` |
| **DocDD** | Documentation-Driven Development: документ меняется раньше кода и остаётся источником правды |
| **Domain** (область, предмет) | Идентификатор предмета в графе (`subject.id`), например `ml` или `теория-музыки` |
| **Error-log** | Поток ошибок из оценённой продукции, превращаемый в карточки SRS (`source='error_log'`) |
| **FR / NFR** | Функциональное / нефункциональное требование, `10-requirements/` |
| **FSD** | Feature-Sliced Design — методология слоёв клиента: `app` → `pages` → `widgets` → `features` → `entities` → `shared` |
| **FSRS** | Free Spaced Repetition Scheduler — алгоритм интервального повторения (`ts-fsrs` на клиенте) |
| **Grade** | Результат оценки по рубрике: критерии, `overall`, `errors[]`, `exemplar` |
| **Job** | Отложенная AI-задача, мост offline → online: `pending` → `running` → `done` / `failed` |
| **LocalGrader** | Офлайн-fallback модуля: мгновенный черновой сигнал без LLM |
| **LWW** | Last-write-wins — стратегия разрешения конфликтов sync на уровне записи |
| **Mastery** (освоенность) | Персональная оценка узла: бета-распределение (`alpha`, `beta`), `estimate`, `confidence`, `bloom_reached` |
| **Module** (модуль) | Предметная область-плагин (`languages`, `ml`, `knowledge`): типы Activity, рендереры, рубрики, генераторы |
| **Probe** (зонд) | Одиночное задание плейсмента на границе знаний |
| **Rubric** (рубрика) | Версионированный промпт-оценщик: `(id, version)`, `prompt`, `schema`, `model` |
| **SPEC** | Спека возможности, `20-specs/SPEC-<NN>-*.md` |
| **SRS** | Spaced Repetition System — интервальное повторение |
| **Subject** (предмет) | Выбор человека в онбординге: `profile.subject = {id, title, target}` |
| **ЗБР** | Зона ближайшего развития (Выготский): узел вводится, когда его предпосылки освоены |
| **Граница знаний** (фронтир) | Узлы, у которых предпосылки освоены, а сам узел ещё нет |
| **Курс** | Персональный путь по узлам до цели. Строится стадиями: укоренение → дифференциация → ветвление → спираль |
| **Плейсмент** | Адаптивная проверка уровня: зонды на границе знаний, результат — карта освоенности |
| **Шаг курса** | Узел пути; разворачивается в цепочку активностей `concept_study → concept_recall → [contrast] → [apply] → srs` |
