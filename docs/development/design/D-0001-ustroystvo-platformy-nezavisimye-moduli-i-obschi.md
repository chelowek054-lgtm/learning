# Устройство платформы: независимые модули и общий шлюз

Под вектор платформы графов знаний и мини-приложений система делится на пять относительно независимых модулей, общающихся только через общий шлюз: (1) графы знаний — общие и персональные графы, своя база, векторный поиск для переиспользования областей, наружу отдаёт данные только через шлюз; (2) мини-приложения — читают/запоминают/проверяют знания графа через шлюз, своих копий графа не держат, способ меняется на лету; (3) шлюз — регистрирует модули, держит контракты CRUD между ними, версия контракта; (4) администрирование — модерация базовых графов и пользователей, feature flags; (5) внешняя коммуникация — группы и обсуждения вокруг области (соответствует возможности `community` в функциональной карте).

Готово, когда: принято решение о развёртывании модулей (единый процесс с границами как у сервисов, либо отдельные сервисы); описан контракт шлюза — регистрация модуля, манифест, версия, CRUD-операции к другим модулям; для каждого модуля явно, какими данными он владеет и что получает только через шлюз.

Не дробим на сетевые сервисы раньше, чем граница проверена кодом в одном процессе; не даём модулю ходить в чужую базу напрямую, даже «временно».
