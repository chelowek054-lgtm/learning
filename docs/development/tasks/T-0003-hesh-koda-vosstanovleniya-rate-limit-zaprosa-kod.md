# Хеш кода восстановления, rate-limit запроса кода, отзыв сессий после смены пароля

Сейчас код восстановления хранится в БД открыто (осознанно, до доставки), а прежний токен остаётся годным после смены пароля. Нужно: хешировать код в БД; ограничить частоту запроса кода по email/IP; ввести версию токена у пользователя, чтобы смена пароля инвалидировала прежние сессии. Готово, когда: старый токен → 401 после смены пароля; частые запросы кода → 429 (тест).
