# Изоляция модулей и защита данных от утечек

Зачем: R-0030 — сторонний модуль не должен достать до чужих данных, выйти в сеть без разрешения и уронить ядро; без этого нельзя открывать подключение модулей людьми.
Делаем: модуль исполняется в изолированной среде без прямого доступа к файлам, базе, секретам и памяти других модулей, единственный путь к данным — интерфейс платформы с проверкой разрешений; сеть закрыта по умолчанию, открыты только объявленные при установке адреса; ресурсы ограничены (время, память, число обращений, размер хранилища), превышение останавливает модуль, не систему; сбой модуля не роняет ядро; расширение разрешений при обновлении требует нового согласия человека.
Не делаем: не полагаемся на честность авторов, не открываем каталог без изоляции и проверки.
Готово, когда: специально написанный «злой» модуль не получает чужих данных и не выходит за ограничения — проверено тестом.
