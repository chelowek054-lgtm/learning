# Единое хранилище данных пользователя с доступом по разрешениям

Зачем: R-0031 — данные учащегося принадлежат платформе, а не модулям; смена способа запоминания не должна терять накопленное.
Делаем: все данные пользователя — в одном хранилище с единым журналом событий, без собственных таблиц личных данных у модулей; у каждого типа данных описан владелец, назначение, срок хранения; модуль получает только объявленные в манифесте и разрешённые типы данных, чтение и запись разрешаются отдельно; доступ пишется в журнал, который человек может прочитать; человек может отозвать разрешение, выгрузить и удалить данные целиком, включая то, что модуль успел запросить; офлайн-режим и локальная БД как источник правды сохраняются.
Не делаем: не отдаём модулю «весь профиль» по умолчанию, не смешиваем данные разных людей в одном ответе.
Готово, когда: модуль без разрешения получает отказ, доступ в журнале, отзыв/выгрузка/удаление работают.
