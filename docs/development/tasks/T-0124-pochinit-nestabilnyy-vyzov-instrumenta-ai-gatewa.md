# Починить нестабильный вызов инструмента AI-gateway в живых проверках

Повторный прогон live_checks.py (placement, profile, rubrics) падает при зелёных локальных тестах и доступной сети. В базе видно job grade_writing с ошибкой «модель не вызвала инструмент submit_grade (finish_reason=stop)» после 3 попыток; похожие сбои у placement («зондов 5, нужно не меньше шести») и profile («0 понятий») — тот же класс нестабильности структурированного ответа.

Что сделать: разобраться, ведёт ли себя модель по умолчанию нестабильно при tool calling, и нужен ли запасной вызов другой моделью после неудачных попыток или ужесточение tool_choice. Переиспользует существующий транспорт `learningBack/core/ai_openai.py` (там уже есть цикл повторов и адаптация max_tokens) — чинится логика там, новый транспорт не создаётся.

Готово, когда: десять подряд прогонов rubrics, placement и profile проходят без ручного повтора (см. verification).

Чего не делаем: не ослабляем сами проверки ради зелёного результата.
