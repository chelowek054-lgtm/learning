# Единый контракт модуля и реестр для платформы

Зачем: R-0027 и контракт C-0001 пока без работы, которая их выполняет; это основа перехода к платформе (фаза P-0015) — без одного контракта граф, данные и способы запоминания нельзя разделить честно.
Делаем: сводим серверный и клиентский манифесты в одно описание модуля по C-0001 (идентификатор, версия, версия контракта ядра, что даёт/просит); ядро проверяет манифест и отказывает с понятной причиной на несовместимой версии, занятом идентификаторе, неизвестном запросе; вводим жизненный цикл (установка, включение, отключение, обновление, удаление) без удаления данных при отключении; переводим три базовых модуля (граф, повторение, письмо) на новый контракт без изменения поведения для учащегося.
Не делаем: контракт «на вырост» с лишними точками расширения; не открываем подключение сторонних модулей.
Готово, когда: три базовых модуля подключены по новому контракту, несовместимые/конфликтующие манифесты отклоняются с причиной, поведение для учащегося не изменилось.
