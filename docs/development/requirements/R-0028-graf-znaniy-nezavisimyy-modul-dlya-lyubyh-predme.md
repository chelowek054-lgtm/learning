# Граф знаний — независимый модуль для любых предметов

Зачем: граф знаний — структурное ядро идеи, должен обслуживать любой предмет. Сейчас он вынесен в пакет, но выбирает «язык или технологии» по названию предмета.

Что нужно: один модуль графа для всех предметных областей; разница между областями — в содержимом узлов и привязанных способах запоминания, а не в коде графа.

Готово, когда: модуль графа не знает ни одного предмета (нет проверок по названию, предметных рубрик, предметного стартового контента); граф отдаёт стабильный интерфейс (узел и связи, граница знаний, чтение/запись освоенности, подписка на изменение узла); канон и персональный слой работают одинаково для любой области; задания, плейсмент и курс подключаются к графу через интерфейс, а не как его внутренности; языковая область (менее иерархичная, чем ML) проверена отдельно, допущения с ML не переносятся молча.

Не делаем: не встраиваем в граф способы запоминания; не храним в графе личные данные пользователя.

Что мешает: освоенность сейчас хранится внутри модуля знаний — нужен общий интерфейс «свидетельство об освоении»; курс и плейсмент написаны под один способ проверки; выбор предмета по названию зашит в провижининг.
