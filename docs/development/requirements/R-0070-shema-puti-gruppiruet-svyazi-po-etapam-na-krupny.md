# Схема пути группирует связи по этапам на крупных графах

Зачем: десятки ломаных линий между колонками делают схему нечитаемой на реальном графе. Что делаем: обзор по этапам (блок с названием, областью, счётом освоенности, полосой; между этапами — одна стрелка со счётчиком связей, толщина растёт с числом; клик на стрелку — список связей); раскрытие этапа на месте (его понятия и связи, остальные этапы — блоками со стрелками-счётчиками, понятия со связями наружу отмечены как «порт», путь «Все этапы › Х» и сводка «опирается на / открывает»); у выбранного понятия рисуются только его прямые связи, соседи из свёрнутых этапов — «призраками» с подписью этапа, больше 8 — свёртка в «ещё N из этапа Х», кнопка «Вся цепочка» показывает все предпосылки без выбора. Длинные связи без выбора не тянутся через схему — только метка-счётчик на узле. Обзор включается сам по порогу (>25 понятий или >40 связей и ≥2 этапа), переключатель «Этапы/Всё» есть всегда, выбор запоминается. Одинаково в «Карте» и «Дереве», встроенно и во весь экран. Чего не делаем: силовую укладку и перетаскивание узлов, склейку связей в пучки, новые библиотеки графов, свёртку по области (уровень выше этапа — пока обычно одна-две области на цель, не нужно). Что мешает: нужен дизайн-макет трёх уровней до кода (Claude Design).
