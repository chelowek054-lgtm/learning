# Аккаунт: регистрация, вход, восстановление пароля, роли

Зачем: отделить данные одного учащегося от другого и дать администратору права на курирование канона без внешнего провайдера авторизации. Система обязана: регистрировать по email/паролю (от 6 символов) с сразу выданной сессией; входить по email/паролю с одним ответом на неверную пару; восстанавливать пароль одноразовым 8-значным кодом с TTL и лимитом попыток, не раскрывая существование email; доставлять код восстановления на почту; после смены пароля инвалидировать прежние сессии и ограничивать частоту запроса кода; выдавать роль администратора только из CLI. Готово, когда: признаки FR-AUTH-01..07 выполнены; доставка кода и отзыв сессий — до публичного релиза (Ф6).
