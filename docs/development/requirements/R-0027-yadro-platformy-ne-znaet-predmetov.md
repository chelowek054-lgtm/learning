# Ядро платформы не знает предметов

Зачем: сегодня в ядре и базовых модулях есть предметные вещи (колода слов английского, рубрики письма, демо-задания, выбор «язык или технологии» по названию) — это мешает подключать предметы без правки ядра.

Что нужно: ядро держит только общее для любого предмета и способа — граф понятий, хранилище данных пользователя, реестр модулей/разрешений/версий контракта, синхронизацию, очередь задач, офлайн. Любой предмет подключается без правки ядра и базовых модулей.

Готово, когда: способ запоминания — отдельный модуль, включается/отключается/заменяется без правки графа и данных пользователя; модуль читает и пишет данные пользователя только в пределах разрешений, лишнее отклоняется и журналируется; поломка одного модуля не роняет ядро и не достаёт до чужих данных; текущие возможности (повторение, письмо, граф, плейсмент, курс) работают как модули поверх ядра без изменения поведения для учащегося.

Не делаем: не разбиваем на сетевые микросервисы заранее — границы сперва как контракты внутри одного развёртывания; не открываем каталог сторонних плагинов до готовности контракта, разрешений и изоляции; не переписываем работающее ради схемы.
