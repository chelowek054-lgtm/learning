# Автоматические проверки и защита ветки main в CI

Зачем: красный тест или нарушенный инвариант должен блокировать merge, а не обнаруживаться позже. Система обязана: гонять на каждый push/PR в каждом из трёх репозиториев ruff format/check + pytest (backend), npm run check (клиент), скрипт инвариантов и проверку ссылок документации (суперпроект); держать границы FSD линтером, а не только ревью; блокировать merge в main при красном CI. Готово, когда: CI зелёный (уже так, 2026-09-30) и merge заблокирован без зелёного прогона.
