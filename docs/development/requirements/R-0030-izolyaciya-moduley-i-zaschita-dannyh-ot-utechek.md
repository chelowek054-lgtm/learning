# Изоляция модулей и защита данных от утечек

Зачем: как только модули пишут сторонние люди, каждый — потенциальный источник утечки (прочитать лишнее, отправить данные наружу, сломать ядро, съесть ресурсы). Платформа должна быть безопасной по построению, а не по доверию к автору.

Что нужно: модуль исполняется в изолированной среде без прямого доступа к файловой системе, базе, секретам и памяти других модулей — единственный путь к данным — интерфейс платформы с проверкой разрешений; сетевой доступ закрыт по умолчанию и открывается только на объявленные адреса, видимые человеку при установке; ресурсы ограничены (время, память, обращения, хранилище), превышение останавливает модуль, а не систему; сбой модуля не роняет ядро и другие модули.

Готово, когда: личные данные не покидают платформу сверх разрешённого; перед публикацией модуль проходит проверку (манифест, разрешения, статический разбор, ручной просмотр для тех, кто просит много); обновление, расширяющее разрешения, требует нового согласия человека; специально написанный «злой» модуль не получает чужих данных и не выходит за ограничения.

Не делаем: не полагаемся на честность автора; не выдаём разрешения «на всякий случай»; не открываем публичный каталог до готовности изоляции и проверки.

Что мешает: не решено, где исполняются модули; нет модуля данных пользователя с разрешениями и контракта модуля, поверх которых строится защита.
