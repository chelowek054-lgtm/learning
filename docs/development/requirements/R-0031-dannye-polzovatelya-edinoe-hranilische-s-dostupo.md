# Данные пользователя: единое хранилище с доступом по разрешениям

Зачем: данные учащегося (ответы, оценки, освоенность, карточки, заметки, результаты мини-игр, голос) — самое ценное и опасное в системе; если каждый модуль хранит их как хочет, защитить их нельзя и человек не может сменить способ запоминания, не потеряв прогресс.

Что нужно: все данные пользователя — в одном хранилище с единым журналом событий, модуль не заводит свои таблицы с личными данными в обход; у каждого типа данных есть владелец, назначение и срок хранения; модуль получает доступ только к объявленным в манифесте и разрешённым человеком типам данных, чтение и запись разрешаются отдельно; любой доступ модуля пишется в журнал (кто, что, когда, зачем).

Готово, когда: человек может отозвать разрешение, выгрузить данные целиком и удалить их — удаление доходит и до данных, которые запросил модуль; данные модуля, не относящиеся к личным, хранятся отдельно и удаляются вместе с модулем; офлайн-режим сохранён — локальное хранилище остаётся источником правды, синхронизация идёт через платформу.

Не делаем: не отдаём модулю «весь профиль» по умолчанию; не позволяем отправлять личные данные наружу в обход платформы; не смешиваем данные разных людей в одном ответе модулю.

Что мешает: политика данных ещё не написана; данные сейчас размазаны по разным таблицам; голос — биометрия, правила его хранения не решены.
