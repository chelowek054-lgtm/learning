# Единый примитив Activity и доменно-независимая модульная регистрация

Зачем: дать один примитив, через который проходит любое учебное взаимодействие, и подключать предметы модулями, не трогая ядро. Система обязана: диспетчеризовать по activity.type табличным поиском (коллизии и повторная регистрация отклоняются с ошибкой); брать название и подсказку типа из реестра, а не из экранов; показывать незнакомый тип плейсхолдером, а не падением; давать модулю объявить офлайн-грейдер; на backend регистрировать модули через общий контракт (core.modules), ядро не знает их имён. Готово, когда: ни shared/engine, ни learningBack/core не содержат предметных строк и импортов modules.*.
