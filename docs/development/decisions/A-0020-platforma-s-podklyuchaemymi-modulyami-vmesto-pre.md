# Платформа с подключаемыми модулями вместо предметных модулей

Зачем: деление по предметам (языки, ML) не масштабируется на третий-десятый предмет — каждый тянет свои рубрики, типы заданий, контент, и ядро приходится дополнять. Замысел шире: дать людям создавать свои инструменты запоминания.

Что решили: делить систему по задачам, а не по предметам. Ядро — реестр модулей, разрешения, синхронизация, очередь задач, офлайн. Модуль графа знаний — один для всех предметов. Модули способов запоминания — любое число (сейчас: повторение, письмо). Модуль данных пользователя — единственный владелец личных данных. Предметы — содержимое графа и подключённые способы запоминания, не код ядра. Границы — контракты внутри одного развёртывания; сетевые сервисы и публичный каталог — позже, когда появится причина.

Отвергнуто: предметные модули как сейчас (ядро правится под каждый предмет, нельзя дать людям свои инструменты); сразу сетевые микросервисы (тяжёлая инфраструктура и сеть до проверки границ, мешает офлайну); плагины-код без изоляции (не годится для сторонних авторов, нет защиты данных).

Последствия: часть уже заведённых требований (код-задачи, письмо Task1/TOEFL, чтение/аудирование, речь, граф для языка) становится модулями или пакетами контента, а не требованиями к ядру; задачи, закрепляющие прежнюю форму (тип повторения в курсе, выбор предмета при регистрации), нужно пересмотреть до начала.
