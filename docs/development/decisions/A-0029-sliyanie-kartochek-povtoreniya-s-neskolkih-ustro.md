# Слияние карточек повторения с нескольких устройств по последнему ревью

Выбор: состояние карточки повторения, пришедшее с разных устройств, сливается по последнему ревью (`last_review`), а не по времени записи на сервер. Побеждает состояние с более поздним `last_review`; при равном времени — с большим числом повторов, затем с большим числом провалов; равные состояния повторно не принимаются. Правило одно и дублируется на сервере (`core/srs.py`) и на клиенте (`card-merge.ts`). Ответы (`response`) неизменяемы и конфликтов не дают.

Почему: устройство, которое повторяло карточку раньше по времени обучения, но синхронизировалось позже другого устройства, не должно откатывать интервал, уже выставленный этим другим устройством. Время записи на сервер отражает порядок синхронизации, а не порядок обучения.

Отвергнуто: слияние по времени записи (прежнее поведение) — откатывает интервалы, если устройства синхронизируются в другом порядке, чем повторяли. Слияние по полному журналу ревью с пересчётом состояния — точнее, но требует хранить и передавать журнал повторений; избыточно для текущего размера данных.

Последствия: если два устройства повторили одну карточку независимо, учитывается только более позднее ревью — промежуточное повторение с более раннего устройства теряется в состоянии карточки (сам ответ в журнале остаётся).
