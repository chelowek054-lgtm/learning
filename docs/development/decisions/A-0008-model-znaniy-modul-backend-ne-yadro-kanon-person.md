# Модель знаний — модуль backend, не ядро; канон + персональный слой copy-on-write

Принято 2026-08-23. Слой графа сначала жил в core/, вопреки инварианту доменной независимости; граф нужен одновременно общий (кураторский) и персональный (растущий под интересы), а копировать канон каждому пользователю дорого и не получает улучшений канона. Решено вынести слой в modules/knowledge/ (зависимость только knowledge→core, ядро даёт лишь доменно-нейтральный AIGateway.structured); таблицы делят общую core.db.Base. Граф двухуровневый: канон (concept, concept_edge) и персональный слой (user_concept, user_edge) — новый пользователь читает канон напрямую, правка или рост создают персональную строку поверх; освоенность всегда персональная. Проверяется grep по core/ на отсутствие логики графа.
