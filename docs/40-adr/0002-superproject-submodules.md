# ADR-0002 — Суперпроект с сабмодулями; оркестрация в корне, Dockerfile у сервиса

| | |
|---|---|
| **Статус** | `accepted` |
| **Дата** | 2026-07-04 |
| **Затрагивает** | SPEC-17, NFR-16 |

## Контекст

Система состоит из клиента (Expo) и backend (FastAPI) с разными языками, инструментами и циклами релиза. Документация и оркестрация относятся к обоим.

## Решение

Корневой репозиторий `learning` — **git-суперпроект**. В нём лежат `docs/`, `ROADMAP.md`, `docker-compose.yml`, `.env.example` и `.data/`. Сервисы — сабмодули `learningFront` и `learningBack`, у каждого свой `main` и origin. `Dockerfile` сервиса лежит в его сабмодуле, корневой compose собирает их вместе. Новый сервис — новый блок в compose и свой Dockerfile.

## Рассмотренные варианты

| Вариант | За | Против |
|---|---|---|
| Монорепо с workspaces | Один коммит на сквозное изменение | Смешение Python- и npm-инструментов (исходный план с `apps/mobile` отвергнут) |
| Отдельные репозитории без суперпроекта | Независимость | Документации и оркестрации негде жить |
| Суперпроект + сабмодули | Документы и оркестрация рядом с обоими сервисами; сервисы независимы | Коммитить и пушить нужно три репозитория и поднимать указатели |

## Последствия

Сквозное изменение — это три коммита: по одному в каждом сабмодуле и подъём указателей в суперпроекте ([HANDOFF §1](../HANDOFF.md#1-что-это)). На файлы сабмодулей `docs/` ссылается путями в тексте, а не markdown-ссылками: по ссылке из суперпроекта GitHub не открывает файл внутри сабмодуля.
