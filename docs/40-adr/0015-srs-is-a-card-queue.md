# ADR-0015 — Повторение — очередь карточек, а не тип Activity

| | |
|---|---|
| **Статус** | `proposed` |
| **Дата** | 2026-09-30 |
| **Затрагивает** | SPEC-05, SPEC-11, FR-SRS-06 |

## Контекст

Модули объявили три типа повторения: `vocab_srs` (languages), `concept_srs` (ml) и `srs` (knowledge — его отдаёт шаг курса). Ни у одного нет рендерера Activity: на деле повторение идёт экраном карточек по `srs_card`. Шаг курса со `srs` не исполняется, а типы разошлись между клиентом и backend.

## Решение

**Предлагается:** повторение — не тип Activity, а очередь `srs_card` с единым экраном.

- Типы `vocab_srs`, `concept_srs` и `srs` удаляются из манифестов.
- Вместо активности `srs` шаг курса указывает карточку узла (`concept_id`), и экран курса ведёт на её повторение.
- Поле `module` у карточки остаётся для фильтрации и метрик.

## Рассмотренные варианты

| Вариант | За | Против |
|---|---|---|
| Один тип Activity `srs_review` с рендерером карточки | Единообразие с остальными Activity | Дублирует экран повторения; Activity на каждую карточку |
| Очередь карточек | Уже так работает; один источник | Шаг курса ссылается на сущность вне Activity |

## Последствия

Решение принимается в P3-SRS-01. После принятия нужно поправить 02-logical §1, SPEC-01 (таблица типов) и SPEC-11 (цепочка активностей).
