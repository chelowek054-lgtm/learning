# ADR-0009 — Провайдер LLM задаётся конфигурацией; один OpenAI-совместимый gateway

| | |
|---|---|
| **Статус** | `accepted` |
| **Дата** | 2026-08-25 |
| **Затрагивает** | SPEC-04, NFR-02 |

## Контекст

Провайдер менялся трижды: Claude через SDK Anthropic, OpenRouter, RouterAI. Каждый раз выбор провайдера расползался по коду: отдельный класс, подхват `OPENROUTER_API_KEY` по подстроке адреса, слаг модели в рубриках.

## Решение

Любой сервис с `/chat/completions` и tool calling обслуживает один класс `OpenAICompatibleGateway`. Всё, что зависит от провайдера, задаётся конфигом:

- адрес — `LLM_BASE_URL`, ключ — `LLM_API_KEY`;
- модели — `LLM_MODEL_SCORING` и `LLM_MODEL_GENERATION`. Рубрика может задать свою `model`; если поле пустое, модель берётся из конфига.

Без ключа работает `MockAIGateway`. Модули проверяют наличие LLM через `has_llm()`. `max_tokens` обязателен в каждом запросе. Обрыв канала, 402 и текстовый ответ вместо вызова инструмента транспорт повторяет до трёх раз.

## Рассмотренные варианты

| Вариант | За | Против |
|---|---|---|
| Класс на провайдера | Специфичные возможности вендоров | Выбор провайдера в коде; ветки расходятся |
| Один OpenAI-совместимый класс | Смена провайдера без правки кода | Нет специфичных возможностей вендоров |

## Последствия

Смена провайдера сводится к правке `.env`. Миграция `0008` вычистила из рубрик слаги прежнего провайдера. Сейчас используется RouterAI с моделью `deepseek/deepseek-v4-flash-0731`.
