# ADR-0010 — Один `.env` в корне суперпроекта для всех сервисов

| | |
|---|---|
| **Статус** | `accepted` |
| **Дата** | 2026-08-25 |
| **Затрагивает** | NFR-16 |

## Контекст

До 2026-08-25 файлов окружения было три, и они молча расходились. Ключ лежал в одном файле, адрес провайдера — в другом, и приложение работало на заглушках без единой ошибки.

## Решение

Единственный источник окружения — корневой `.env`:

- его читает docker-compose и `learningBack/core/config.py` (переменные окружения приоритетнее файла);
- `learningFront` переносит `EXPO_PUBLIC_*` в свой `.env` скриптом `sync-env.js` на хуках `pre*` перед каждым `npm start`/`web`, потому что Expo читает только свой корень;
- `DATABASE_URL` не задаётся отдельно, а собирается из `POSTGRES_*`.

## Рассмотренные варианты

| Вариант | За | Против |
|---|---|---|
| `.env` на сервис | Независимость | Молчаливое расхождение |
| Один корневой | Один источник правды | Клиенту нужен перенос скриптом |

## Последствия

`learningFront/.env` генерируется и перезаписывается, поэтому править нужно корневой файл. `.gitignore` ловит все `.env*`.
