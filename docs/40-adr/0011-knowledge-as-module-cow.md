# ADR-0011 — Модель знаний — модуль backend, не ядро; канон + персональный слой copy-on-write

| | |
|---|---|
| **Статус** | `accepted` |
| **Дата** | 2026-08-23 |
| **Затрагивает** | SPEC-08, NFR-KG-1, NFR-KG-3 |

## Контекст

Слой графа сначала жил в `core/`, вопреки собственному инварианту. Граф нужен одновременно общий (кураторский) и персональный (растущий под интересы). Копировать канон каждому пользователю дорого, и такая копия не получает улучшений канона.

## Решение

- Слой вынесен в пакет `learningBack/modules/knowledge/`: свои модели, схемы, COW, centrality, AI-роли, роутер. Зависимость направлена в одну сторону: `knowledge → core`. Ядро даёт только доменно-нейтральный `AIGateway.structured`.
- Таблицы делят общую `core.db.Base`, поэтому миграционная линия одна.
- Граф двухуровневый: канон (`concept`, `concept_edge`) и персональный слой (`user_concept`, `user_edge`). Новый пользователь читает канон напрямую; правка или рост создают персональную строку поверх. Освоенность всегда персональная.

## Рассмотренные варианты

| Вариант | За | Против |
|---|---|---|
| Граф в ядре | Проще доступ | Нарушает доменную независимость |
| Копия канона на пользователя | Простое чтение | Дорого; улучшения канона не доходят |
| Модуль + COW | Ядро чистое; улучшения канона видны всем, у кого нет оверрайда | Чтение сложнее: нужен эффективный граф |

## Последствия

Проверка: grep по `core/` не находит логики графа. На клиенте `shared/engine` про граф тоже не знает.
