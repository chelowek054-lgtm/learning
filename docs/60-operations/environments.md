# Среды: local, staging, production

> Черновик (T-0031). Хостинг не выбран (T-0030, предложение — `docs/inbox/decision-hosting.md`); всё ниже не привязано к площадке: нужен сервер с Docker и Compose v2.24+.

## Что где

| | local | staging | production |
|---|---|---|---|
| Запуск | `docker compose up -d` | `scripts/deploy-staging.sh` | не определён (после T-0030) |
| `APP_ENV` | development | staging | production |
| Секреты | dev-значения допустимы | обязательны, иначе сервер не стартует | то же, что staging |
| База | порт 5432 открыт | только внутри сети compose | — |
| Воркер задач | по профилю | всегда (`JOBS_MODE=worker`) | — |
| pgAdmin | есть | нет | нет |

## Подготовка staging-сервера

1. Установить Docker с Compose v2.24+, склонировать `learning` с сабмодулями.
2. Создать `.env` рядом с `docker-compose.yml` (см. `.env.example`). Обязательны: `POSTGRES_PASSWORD`, `JWT_SECRET` (не короче 32 символов, случайный), `CORS_ORIGINS` (адрес клиента), `LLM_API_KEY`. Ни одно значение не должно быть dev-умолчанием: сервер откажется стартовать (T-0032).
3. Поставить перед API обратный прокси с TLS (Caddy или nginx) на порт `API_PORT` (8000).
4. Поставить расписание в cron, например раз в сутки: `scripts/backup-db.sh && scripts/restore-check.sh` и `docker compose exec -T api uv run python -m scripts.purge_expired`.

## Деплой

```bash
scripts/deploy-staging.sh
```

Скрипт подтягивает `main`, собирает образы, поднимает базу, делает копию и проверяет, что она восстанавливается, затем поднимает API и воркер. Миграции применяются командой запуска контейнера до старта сервера. Если `/health` не ответил, скрипт завершается с ошибкой и подсказывает откат.

## Резервные копии

- `scripts/backup-db.sh [каталог] [дней]` — сжатый дамп в `.data/backups`, хранится 14 дней по умолчанию.
- `scripts/restore-check.sh [файл]` — накатывает копию во временную базу `restore_check`, сверяет версию миграции и число таблиц с рабочей базой и удаляет временную. Копия, не прошедшая проверку, копией не считается.
- Копии лежат на том же сервере: **вынесите их на другой носитель или в другое место** — это не сделано и зависит от выбора хостинга.

## Откат

1. `git checkout <прежний коммит>` и `docker compose -f docker-compose.yml -f deploy/docker-compose.staging.yml up -d --build`.
2. Если миграция уже применилась и несовместима: остановить API, восстановить базу из копии, сделанной перед деплоем:
   `gzip -dc .data/backups/praxis-ГГГГММДД-ЧЧММСС.sql.gz | docker compose exec -T postgres psql -U praxis -d praxis`
   (дамп сделан с `--clean --if-exists`, накатывается на непустую базу).
