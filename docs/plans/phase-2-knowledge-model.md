# Фаза 2 — Модель знаний и адаптивные курсы

> **Статус: завершена (код).** Все пять потоков закрыты, DoD и инварианты прогнаны на живом стенде 2026-08-23. Не проверено на устройстве — только web и сборка.

**Цель фазы:** построить слой **модели знаний** (граф концепций как ядро-актив) и доказать на ML сквозную цепочку: **канонический граф → наследование новым юзером (COW) → адаптивный плейсмент → генерация курса до целевого уровня**, где узел хранит формализованную теорию, из которой генерятся тест и практика.

Архитектура слоя — [05 — Модель знаний](../architecture/05-knowledge-model.md). Строится **над** движком Activity ([02](../architecture/02-logical.md)), ядро остаётся доменно-независимым.

**Решения (зафиксированы):**
- **Первая тема:** ML/программирование (граф естественно иерархичен).
- **Источник графа:** LLM генерирует → пользователь правит (Approve/Edit/Reject).
- **Канон ↔ персонал:** **copy-on-write** (наследование базы + персональный рост поверх).
- **Тир узла:** `core` (фундаментальное **обязательное** ядро) vs `derived` (вытекающие ветви поверх ядра).
- **Курс = симуляция развития** (укоренение → дифференциация → ветвление → спираль), не топосорт. См. [05 §7](../architecture/05-knowledge-model.md#7-развитийная-модель-курса).
- **Приоритет:** строим новый слой (не полируем MVP).

**Не входит:** промоция персональных узлов в канон (курирование), полноценный IRT-плейсмент, языковой домен, сообщество. Позже.

**Предпосылки:** Фаза 1 завершена (движок Activity, AI-gateway + Mock, FSRS, sync, auth). Клиент — Expo SDK 54.

> ⚠️ Реальная генерация графа/оценок требует `CLAUDE_API_KEY`; без ключа — `MockAIGateway` (детерминированные заглушки графа/оценок для разработки).

## Definition of Done фазы

1. ✅ Канонический граф ML существует (LLM-черновик, отредактирован) — узлы с теорией + prereq/specializes-связи; **фундаментальное ядро размечено** (`tier=core`).
2. ✅ Новый пользователь наследует канон (COW); правка/рост создают персональные `derived`-узлы поверх; **курс не ведёт к цели в обход непокрытого ядра**.
3. ✅ Полный **CRUD** графа (узлы/связи/контент) через API + редактор на клиенте; LLM-предложения идут как draft с confidence.
4. ✅ Из `content` узла генерятся тест-айтемы и практика (заземлённые, кэш, теги Блума).
5. ✅ Адаптивный плейсмент: первый шаг — целевая ступень; зонды по узлам; байес-lite → карта mastery.
6. ✅ Генерация курса: топосорт пробела → цепочки активностей с нарастанием Блума + FSRS; экран курса/прогресса.
7. ✅ Инварианты §10 [05](../architecture/05-knowledge-model.md#10-инварианты-слоя-добавляются-к-системным): ядро без графа, генерация заземлена на content, персонал поверх канона (COW), версии узлов, LLM-draft с confidence.

## Рабочие потоки

Порядок: **KG1 → KG2 → KG3 → KG4 → KG5** (KG5 нужны оценки из KG3 и mastery из KG4).

```
KG1 Данные графа (canonical+personal COW, CRUD API)
KG2 Построение/рост графа (LLM draft) + редактор графа (CRUD UI, governance)
KG3 Узел-контент → генерация оценок (тест/практика) из теории
KG4 Адаптивный плейсмент (target-first, байес-lite mastery)
KG5 Генерация курса + экран прогресса (интеграция Activity/FSRS/error-log)
```

## KG5 — Генерация курса + прогресс

**Backend — `generate_course(gap)` как симуляция развития ([05 §7.2](../architecture/05-knowledge-model.md#72-алгоритм-генерации-курса)):**
- [ ] `P2-KG5-01` **Укоренение**: непокрытое `tier=core` вставляется первым (независимо от цели).
- [ ] `P2-KG5-02` **Дифференциация**: от фронтира по `prereq`/`specializes` (общее→частное), в ЗБР; **ветвление**: `derived`-ветки под интересы; сохранить `course.path`.
- [ ] `P2-KG5-03` **Спираль + починка**: пере-подъём ядровых узлов на выше по Блуму; `misconception`-рёбра → контраст-активности. Под узел — цепочка `concept_study → concept_recall → apply → srs` + interleaving.

**Клиент:**
- [ ] `P2-KG5-04` Экран курса: путь по узлам (ядро → ветви), прогресс, «сегодня»; активности исполняются существующим `ActivityDispatcher`.

**DoD KG5:** от карты mastery строится курс до цели; активности идут по графу; FSRS держит удержание; прогресс виден; ретест пересобирает путь.

## Открытые вопросы Фазы 2

1. **Core-детекция** — как метим `tier=core`: centrality графа / частота-как-предпосылки / вручную (вероятно гибрид). Влияет на KG1/KG2.
2. **Гранулярность узла** — критерий «один концепт» (уточнить на реальном ML-графе).
3. **Освоенность:** скаляр vs per-(узел, ступень) — решить в KG4.
4. **Старт калибровки зондов** — эвристика сложности до перехода на IRT.
5. **UX редактора графа на телефоне** — граф на маленьком экране (список+фокус-узел vs canvas).
6. **Стоимость LLM** на генерацию графа/оценок — кэш агрессивно; лимиты.
